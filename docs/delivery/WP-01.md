## Відомі обмеження
- `InMemoryJobStore` / `InMemoryIdempotencyStore` — лише один екземпляр; для кількох екземплярів сервіс реалізує
  протоколи на власній БД (задокументовано).
- `build_mock_app` не валідує query/path/header-параметри (лише JSON-тіло) і повертає перший приклад; для строгої
  перевірки запитів WP-00 рекомендує також Prism. `ContractClient` перевіряє тіло відповіді й статус, не заголовки.
- `jane-codegen`: моделі типізують відповідь лише для схем `#/components/schemas/*` того самого файлу; для
  контрактів WP-00 (схеми в `../schemas/*.json`) методи клієнта повертають `Any` (dict). Моделі для таких схем —
  `jane-codegen models` з бандла (`redocly bundle`), як радить скіл `jane-contracts`.
- Контрактні тести шаблону пропускаються, доки `contracts/` немає в checkout (після злиття WP-00 вони вмикаються
  автоматично).
- `pgsty/minio` — збірка MinIO спільнотою (upstream-образи недоступні без авторизації), SeaweedFS реалізує не весь
  S3 API — обґрунтування в [infra/README.md](../../infra/README.md).
- Перший `just up` на новій машині тягне образи (SQL Server ~1.6 GB) — довше, ніж 24 с із заміру.
- Git pre-commit хук не встановлено автоматично (див. вище); без gitleaks хуки лише попереджають.
- `.gitattributes` задає LF у робочих копіях; щоб наявні checkout із CRLF (через `core.autocrlf=true`) перейшли на
  LF, після злиття потрібне повторне витягнення файлів (`git checkout -- .` у чистому дереві). У репозиторії файли й так LF.

## Неперевірені інтеграції
- CI GitHub Actions локально не запускався (немає runner); ті самі команди перевірено вручну на Windows і в Linux-контейнері.
  Крок Redocly (`JANE_CONTRACTS_REDOCLY=1`, npx) і gitleaks-образ у CI — не перевірені запуском.
- AWS S3 — не перевірено на реальному сервісі (лише SeaweedFS і MinIO).
- `just web` / job `web` — не перевірено на реальному застосунку (його ще немає, WP-12).
- Відповідність WP-00 перевірено на **чернетці**; після прийняття WP-00 потрібен повторний прогін `just contract`.
