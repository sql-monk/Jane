# Admin UI

Admin UI — вебзастосунок оператора Jane: джерела, завдання з ланцюжками етапів і розкладами, запуски, матеріали й результати, проблеми та вдосконалення екстракторів, пакети обробників, підключення, LLM, ліміти й аудит. Код — [web/admin](../../../web/admin/), стек — React 19, TypeScript, Vite, pnpm.

## Межі відповідальності

Admin UI робить:

- показує стан платформи й дані сервісів, отримані через їхні API `/v1`;
- редагує конфігурацію (джерела, завдання, підключення, ліміти, бюджети LLM) й надсилає її сервісам;
- редагує код і правила пакетів і публікує зміни як нову версію в Registry;
- запускає асинхронні операції (запуски завдань, тести, повторну обробку, роботу Assistant) й опитує їхній стан.

Admin UI не робить:

- не має власного сервера й бази: усі дані належать сервісам, браузер зберігає лише ключ сесії й вибрану тему ([будова](internals.md#дані-в-браузері));
- не перевіряє права: доступ визначає кожен сервіс за токеном, Admin UI лише показує `401`/`403`;
- не виконує код екстракторів і не звертається до джерел — це роблять Handler Runtime і колектори через Orchestrator;
- не бачить значень секретів: підключення містять лише посилання `env:`, `file:`, `vault:`.

## Тип і автономність

| Властивість | Значення |
|---|---|
| Тип модуля | інтерфейс |
| Артефакт | статичні файли `web/admin/dist` і `config.json` поруч із ними |
| Окремо | так, на контрактних моках API — без жодного сервісу Jane ([швидкий старт](quickstart.md)) |
| Обов'язкові залежності | API сервісів через reverse proxy з префіксом `/api/<сервіс>` |
| Опційні залежності | постачальник ідентичності OIDC |

Кожна сторінка працює з тими сервісами, які їй потрібні. Недоступний сервіс показує помилку лише на своїх сторінках; решта адмінки працює. Перелік — [інтеграція](integration.md#сторінки-та-api).
