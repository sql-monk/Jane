# Telegram Collector

Telegram Collector отримує повідомлення каналів Telegram — історію, нові повідомлення й редагування — і повертає їх як матеріали через спільний API колекторів `collector.v1`. Тип модуля — колектор; працює окремо, без Orchestrator, Registry і обробників.

## Призначення й межі

| Відповідає за | Не відповідає за |
|---|---|
| історію каналу, нові повідомлення, редагування | збереження повідомлень і результатів — це Storage |
| курсори каналів між зборами (`state_key`) | витягування подій і сутностей — це екстрактори |
| ревізії: редагування — нове спостереження того самого `material_id` | розклади й ланцюжки — це Orchestrator |
| медіа (за правилами), доставку inline або транзитним blob | інтерактивний вхід в обліковий запис Telegram |
| паузи між викликами, FloodWait, повтори | |

## Можливості

- **Разове отримання** — `POST /v1/fetches` повертає одне повідомлення за каналом і `message_id`.
- **Збір** — `POST /v1/collections`: асинхронне завдання (job), матеріали читаються з курсором і підтверджуються.
- **Режими** — `full` читає історію (`history.since`, `history.from_message_id`); `incremental` з курсором читає зміни каналу після збереженого `pts`.
- **Редагування** — нове спостереження з більшим `revision.sequence` і `revision.is_edit: true`; повторна доставка тієї самої ревізії не видається.
- **Медіа** — `media.download` і `media.kinds` (`photo`, `document`, `video`, `audio`), межа `telegram.max_media_bytes`.
- **Кілька екземплярів** — на одному вузлі зі спільним каталогом стану: оренда збору, перехоплення після зупинки екземпляра.

## Бекенди клієнта Telegram

Колектор звертається до Telegram лише через інтерфейс `TelegramClient`; реалізацію обирає `JANE_TELEGRAM_COLLECTOR_CLIENT_BACKEND`.

| Бекенд | Що робить | Стан перевірки |
|---|---|---|
| `recorded` (типово) | відтворює канали з JSON-записів у `RECORDINGS_DIR`; файл перечитується на кожен виклик, тож нові повідомлення й редагування можна дописувати під час роботи | перевірено (тести, цей комплект) |
| `telethon` | MTProto через Telethon (extra `telethon`), обліковий запис — кероване підключення `telegram_account` | **не перевірено на реальному Telegram**: тестового облікового запису в проєкті немає |
| `<module>:<factory>` | власна фабрика клієнта (`ClientFactory`) | залежить від реалізації |

## Автономність

Мінімальне середовище — Python 3.12, uv і каталог записів каналів (бекенд `recorded`) або Telethon з авторизованою сесією. Правила — inline, з `RULES_DIR` або з Registry; стан — файл SQLite у `STATE_DIR`. Звернень до Orchestrator немає. Повний перелік — [dependencies.md](dependencies.md).

## Обмеження

- Бекенд `telethon` не перевірено на реальному сервісі Telegram; його покривають лише спільні тести колектора через бекенд `recorded`.
- Кілька екземплярів узгоджуються лише через спільний файл SQLite на одному вузлі.
- Якщо Telegram повідомляє, що різниця змін завелика, редагування за цей проміжок недоступні: нові повідомлення дочитуються з історії, а в `/errors` з'являється запис `source_unavailable`.
- Інструкції перевірено на Windows 11 (ревізія `48389a3`); на Linux не перевірялися.
