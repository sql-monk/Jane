# WP-31. Налаштування та адаптивна навігація адмінки

**Гілка:** `wp/31-admin-settings-responsive-navigation`. **Ревізія власного коду:** `075f4fb`. **Стан:** review після виправлення R1.

Пакет виконує [погоджений план візуального рев’ю](admin-visual-review-plan.md). Спільні компоненти цього пакета надані іншим виконавцям раннім комітом `d3d9c11`. База завершального коміту — `cbf5971`: це залежність WP-29 з редакторами, українською валідацією та захистом чернеток. Ця залежність окремо проходить перевірку WP-29; її авторство не належить WP-31.

Після власного коду також підключено `67151a3`, ідентичний WP-29 `9fa741b`: native history listener реєструється через `useLayoutEffect` перед listener батьківського BrowserRouter. Власник підтвердив завершений Chromium-сценарій `1 passed (3.6m)`. Ці два файли захисту належать WP-29.

## Результат

- Налаштування підключень, провайдерів, псевдонімів, бюджетів, лімітів, нових пакетів і форків реєструють незбережені чернетки. Закриття редактора, зміна вкладки та вихід із сесії звертаються до спільного захисту. Завершення старішого запиту збереження не позначає новішу чернетку збереженою.
- Псевдоніми вибирають провайдера та його модель із каталогу; бюджети й контексти лімітів вибирають джерела та завдання за назвами. Зміна рівня бюджету прибирає ідентифікатор попереднього рівня. Каталоги мають курсорне дозавантаження з `config.page_size`.
- Підключення мають основні поля для типових несекретних параметрів і додатковий JSON. Моделі провайдера й ліміти доступні через грід вкладених властивостей. Незавершена числова чернетка гріда блокує збереження. Секрети залишаються лише посиланнями.
- Таблиці розрізняють завантаження, помилку та справді порожній результат. Вузькі таблиці перетворюються на картки з назвами колонок; меню згортається до ширини 1024 px, закривається Escape і повертає фокус.
- Станам надано українські назви. Дати показано з явним поясом Києва; діагностика спроб зберігає мілісекунди. Помилки пояснюються за дозволеним кодом, HTTP-статусом і ознакою повторюваності без відображення довільних `title/detail`.
- Підтвердження небезпечних дій — окремий діалог із зазначенням об’єкта. Аудит має часові фільтри, посилання на об’єкти, окремий перегляд «було → стало» й згорнуті технічні деталі. Історична відсутність різниці названа явно.
- Поля мають окремий пов’язаний підпис: варіанти списку та підказка більше не потрапляють до доступної назви поля.

## Виправлення після рев’ю 1

Незалежний рев’юер відтворив три дефекти: редагування create/fork/onboarding під час старішого POST; пізню відповідь відкриття провайдера, яка перезаписувала новий редактор; відсутній доступний підпис вкладеного select VersionPicker та пошукового поля всередині form.

Create/fork/onboarding тепер передають зафіксовані аргументи запиту й блокують свої поля на час виконання. JSON onboarding також стає readOnly. Нові зміни після завершення знову захищає guard. Провайдер ігнорує застарілий номер відкриття, включно із закриттям редактора; відкриття іншого провайдера під час PUT недоступне. VersionPicker містить власний пов’язаний Field, а Field проходить вкладені нативні обгортки. Секретні помилки й попередній захист новішої чернетки підключення збережено.

Додано п’ять адресних регресій на справжніх компонентах: nested search, delayed provider GET та pending create/fork/onboarding. У форку перевірено також labels.length = 1. Підсумки:

```text
$ pnpm exec vitest run src/components/admin-settings.test.tsx --pool forks --maxWorkers 1
Test Files  1 passed (1)
Tests  13 passed (13)
Duration  10.10s

$ pnpm typecheck
$ tsc -p tsconfig.json
exit_code: 0

$ pnpm exec eslint src/components/admin-settings.test.tsx src/components/ui.tsx src/pages/PackagesPage.tsx src/pages/AssistantPage.tsx src/pages/LlmPage.tsx --max-warnings 0
exit_code: 0

$ pnpm exec prettier --check src/components/admin-settings.test.tsx src/components/ui.tsx src/pages/PackagesPage.tsx src/pages/AssistantPage.tsx src/pages/LlmPage.tsx src/styles.css
All matched files use Prettier code style!
exit_code: 0
```

Попередня спроба threads на Windows завершилася помилкою старту worker до виконання settings-файлу; її не зараховано. Наступна forks-спроба знайшла неправильну назву вкладки у новому тесті onboarding (12 passed, 1 failed); після виправлення локатора фінальний набір вище пройшов. Старі Chromium-перевірки адаптивності не повторювалися: відповідний код не змінено. Повний інтегрований CI і робочий стек — наступний гейт WP-32.
