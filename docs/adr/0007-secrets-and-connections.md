# ADR-0007. Секрети й керовані підключення

- **Статус:** прийнято, діє.
- **Звірено з кодом:** ревізія `48389a3`, 2026-10-11.

## Контекст і проблема

Обробники збереження, LLM gateway і колектори потребують облікових даних сховищ, провайдерів і облікових записів. ТЗ вимагає передавати секрети через керовані підключення (ТЗ §11), а пакети не мають містити секретів і не копіюють їх під час форкування (ТЗ §7). Користувач налаштовує підключення в адмінці (ТЗ §10), а сервіси мають працювати й без Orchestrator.

## Варіанти

1. **Підключення = несекретні параметри + посилання на секрети (`secret_refs`); значення розв'язує лише виконавець у своєму середовищі.**
2. Зберігати значення секретів у базі Orchestrator (зашифровано) — Orchestrator стає сховищем секретів, а секрети проходять через API.
3. Секрети в пакеті або конфігурації завдання — порушує ТЗ §7.
4. Вбудоване сховище секретів (Vault) як обов'язкова залежність — важке для локального запуску.

## Рішення

Обрано варіант 1. Схема підключення — [connection.schema.json](../../contracts/schemas/common/connection.schema.json); політика — `libs/jane-kit/src/jane_kit/secrets.py`.

- **Посилання:** `env:ІМ'Я` і `file:/шлях`. `vault:` описаний у схемі, але цією збіркою відхиляється.
- **Політика виконавця:** `env:` лише для змінних із префіксом `JANE_SECRET_`, `file:` лише всередині `/run/secrets` (налаштовується `SECRET_ENV_PREFIX`, `SECRET_FILES_DIR`). Порушення — `secret_ref_not_allowed`.
- **Реєстр підключень** — в Orchestrator (`/v1/connections`, `orchestrator:admin`); значення, схожі на секрети, у `params` відхиляються (`secret_detected`). Orchestrator розсилає визначення виконавцям через `PUT /v1/connections/{id}` їхніх API (`connections:write`); виконавець без керованих підключень відповідає `501`.
- **Автономний режим:** Storage читає підключення з файлу `JANE_STORAGE_CONNECTIONS_FILE`; інші виконавці приймають підключення через власний API.
- **Перевірка підключення** (`…/test`) повідомляє, чи секрети розв'язалися, не показуючи значень.
- **Пакети** декларують лише потрібні підключення (`required_connections`: назва й вид); Registry сканує файли пакетів на секрети.
- **Мережеві адреси підключень** обмежено allowlist-ами виконавця ([безпека експлуатації](../operations/security.md#allowlist-и-мережевих-звернень)).

## Наслідки

- Секрети не потрапляють у бази, журнали, архіви пакетів і форки; резервні копії баз секретів не містять.
- Оператор доставляє значення секретів у середовище виконавця сам (змінні `JANE_SECRET_*`, файли в `/run/secrets`); у dev-стеку ключі провайдерів LLM лежать у `.jane/secrets`, змонтованому лише для читання.
- Поза dev-стеком потрібен зовнішній механізм доставки секретів (секрети оркестратора контейнерів, файли); інтеграції з Vault немає.
