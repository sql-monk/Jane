# ADR-0006 — Підключення із посиланнями на секрети

Дата: 2026-10-11. Основа: `91876d1`. Стан: опис реалізованого рішення; новий текст у review.

## Проблема

ТЗ §7 і §11 вимагають відділити пакет від секретів. Пакети експортуються й форкуються, тому вбудовані облікові дані потрапили б до артефактів та їхніх копій.

## Розглянуті підходи

| Підхід | Наслідок |
|---|---|
| Секрет у params або маніфесті | Простий виклик, але витік через артефакти й API |
| Кероване підключення й secret_ref | Потрібна конфігурація виконавця; пакет лишається переносним |

## Рішення

Connection містить endpoint, options і посилання на секрет. Виконавець розв’язує `env:` або дозволений `file:` у власному середовищі. Orchestrator синхронізує декларації через API; секретні значення не передаються як частина пакета.

## Наслідки

Форк успадковує вимоги, але не облікові дані. Оператор має налаштувати секрет у середовищі потрібного виконавця та обмежити адреси зовнішніх підключень. ContentRef не замінює кероване підключення й не дає читачу credentials сховища.
