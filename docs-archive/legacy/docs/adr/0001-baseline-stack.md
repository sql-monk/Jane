# ADR-0001. Базовий стек

**Статус:** прийнято (WP-00, 2026-09-27)

## Контекст
plan.md §2 зафіксував типові технічні рішення, щоб 11 паралельних агентів хвилі 1 не обирали стек
кожен по-своєму. WP-00 може їх змінити лише через ADR до старту хвилі 1. ТЗ вимагає автономних
компонентів (§4), версіонованих API, асинхронних тривалих операцій, передавання великих матеріалів
за посиланням, роботи на Windows і Linux.

## Рішення
Підтвердити всі рішення plan.md §2 без заміни, з уточненнями:

| Питання | Рішення | Уточнення WP-00 |
|---|---|---|
| Мова сервісів | Python 3.12+, FastAPI, Pydantic v2, uv workspace | Моделі Pydantic генеруються з контрактів (`datamodel-code-generator`), не пишуться вручну. Пакет `contracts/python` (`jane-contracts`) — член workspace |
| Адмінка | TypeScript, React, Vite | Клієнти — `openapi-typescript` + `openapi-fetch` з бандлів контрактів |
| Контракти | OpenAPI 3.1, JSON Schema 2020-12, `/v1` | Спільні компоненти в `contracts/openapi/common.yaml`; лінтер `contracts/tools/check_contracts.py` |
| Взаємодія | Синхронний HTTP; тривалі — 202 + job_id | Потік матеріалів колектора — pull із курсором (ADR-0008); вебхуків у v1 немає |
| Великі матеріали | Посилання на blob-сховище | `ContentRef` inline/blob з TTL (ADR-0004) |
| Службове сховище оркестратора | PostgreSQL, `SKIP LOCKED`, без брокера | Лише для оркестратора; інші сервіси мають власні сховища (ADR-0009) |
| Dev-середовище | Docker Compose, Windows і Linux | Виконання коду екстракторів — лише в контейнері (ADR-0003) |
| Тести | pytest, testcontainers, моки з OpenAPI, Playwright | Моки: `contracts/tools/mock.py` (без Node) або Prism; контрактні тести — schemathesis |

## Наслідки
- Хвиля 1 стартує на відомому стеку; WP-01 будує каркас саме під нього.
- Генерація моделей і клієнтів з контрактів робить контракт єдиним джерелом правди; розбіжність
  ловлять контрактні тести.
- Node.js потрібен лише для адмінки, Redocly і Prism; ядро перевірок контрактів працює на `uv`.

## Альтернативи
- **gRPC/Protobuf** для міжсервісних викликів — відхилено: гірше для сторонніх застосунків і
  адмінки, окремий шлях для великих файлів, менше інструментів для моків на Windows.
- **Брокер повідомлень (RabbitMQ/Kafka/NATS)** — відхилено для v1: PostgreSQL-черга оркестратора
  покриває потреби й не додає обов'язкової інфраструктури; pull-потік колектора дає backpressure.
- **Go/Rust для колекторів** — відхилено: єдиний стек важливіший за продуктивність на цьому етапі.
