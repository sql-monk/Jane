# Застосовність діаграм

Початкова матриця за ролями модулів і джерелами коду. Автор DOC-05 уточнює перелік після дослідження: кожна застосовна схема отримує посилання, незастосовна — конкретну причину у власному internals.md та звіті. Фіксованої кількості схем немає; зміст підтверджує незалежний рецензент.

| Область | Обов’язкові види | Уточнення за кодом | Межі / обґрунтування |
|---|---|---|---|
| Платформа | контекст, компоненти, розгортання, залежності, потоки, послідовності, процеси, сценарії | стани завдань; модель службових даних | класи — у модулях |
| web-collector | компоненти, залежності, класи, потоки, послідовності | SQLite ER, стани збору, алгоритми discovery | користувацькі сценарії — у загальному посібнику |
| telegram-collector | компоненти, залежності, класи, потоки, послідовності | службові дані, стани history/changes | користувацькі сценарії — у загальному посібнику |
| storage | компоненти, залежності, класи, потоки, послідовності, ER | стани запису, idempotency, алгоритми merge | ER окремо для кожного адаптера, без чужих таблиць |
| registry | компоненти, залежності, класи, ER, послідовності | публікація, fork, незмінність версій | workflow автора — в посібнику пакетів |
| handler-runtime | компоненти, залежності, класи, послідовності | службова ER, стани job/sandbox, алгоритм виконання | бізнес-дані належать Storage |
| llm | компоненти, залежності, класи, потоки, послідовності | службова ER, бюджет, стани job | зовнішній provider показується як залежність |
| orchestrator | компоненти, залежності, класи, ER, потоки, послідовності, стани | розклад, branching, повтори | не зображати читання чужих таблиць |
| assistant | компоненти, залежності, класи, потоки, послідовності, сценарії | службова ER, стани onboarding/improvement | активація змін контролюється користувачем |
| jane-kit | класи, залежності, алгоритми | локальні послідовності викликів | власного HTTP-сервісу/БД/розгортання немає |
| extractor-sdk | класи, залежності, процес тестування | локальні послідовності викликів | власного HTTP-сервісу/БД/розгортання немає |
| admin | компоненти, залежності, типи, API-послідовності, сценарії | стани UI і навігації | серверної ER немає; backend схеми в сервісах |

Фактичний рендер та синтаксис перевіряються окремо від семантики. Великі схеми поділяються за питанням, а ER показує власність даних одного сервісу.
