# Ліміти

Ліміти виконання (паралельність, частота запитів, глибина й обсяг обходу, тайм-аути, повтори, розміри, бюджети LLM) не зашиті в код. Вони задаються на рівнях платформа → джерело → завдання → етап: нижчий рівень перекриває вищий, а жорсткі стелі (`hard_caps`) обмежують усі рівні. Нові запуски використовують нові значення. Схема — [limits.schema.json](../../contracts/schemas/common/limits.schema.json).

## Ліміти платформи

Передумова: для зміни ключ має область `orchestrator:admin` (ключ адміністратора dev-стеку її має).

1. Відкрийте «Ліміти» (`/limits`). Розділ «Ліміти платформи» показує поточний документ у JSON-редакторі; якщо застосовано профіль, у заголовку — «(профіль <назва>)».
2. Змініть значення. Редактор перевіряє документ схемою `PlatformLimits` і показує помилки.
3. Натисніть «Зберегти ліміти платформи».

Очікуваний результат: «Збережено». Якщо ліміти тим часом змінив інший користувач, з'явиться помилка `precondition_failed` — перезавантажте сторінку й повторіть зміни. Зміна потрапляє в журнал аудиту з типом об'єкта `limits`.

## Ліміти джерела й завдання

- Джерело: JSON-редактор «Ліміти рівня джерела» на сторінці джерела ([підключення джерела](sources.md#нове-джерело-вручну)).
- Завдання: «Ліміти рівня завдання» на вкладці «Конфігурація» ([завдання й розклад](tasks.md#нове-завдання)).

Обидва редактори перевіряють документ тією самою схемою; зберігаються разом із джерелом чи завданням.

## Ефективні ліміти

Ефективні ліміти — підсумкові значення для конкретного контексту з рівнем, звідки взято кожне.

1. На сторінці «Ліміти» в розділі «Ефективні ліміти для контексту» вкажіть «Джерело», «Завдання» і/або «Етап».
2. Натисніть «Показати».

Очікуваний результат: таблиця «Ефективні ліміти» — параметр (наприклад `crawl.max_depth`), значення й рівень походження. Ту саму таблицю показують «Ефективні ліміти джерела» на сторінці джерела й вкладка «Ефективні ліміти» завдання.

Бюджети LLM за рівнями налаштовуються на сторінці «LLM» — [бюджети](connections-and-llm.md#бюджети).
