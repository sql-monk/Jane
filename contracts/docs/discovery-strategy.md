# Стратегія пошуку матеріалів у Web Collector

Інтерфейс: [`python/src/jane_contracts/discovery.py`](../python/src/jane_contracts/discovery.py).
Конфігурація стратегій — `collector-rules.schema.json#/$defs/Strategy` (поле `type` = `type_name`).

## Власність

| WP | Що реалізує |
|---|---|
| WP-02 (ядро) | `DiscoveryContext` (fetch, нормалізація, scope, robots, ліміти на хост, редиректи, умовні запити, розмір), черга з дедуплікацією й пріоритетами, глибина, повторні відвідування, збереження стану, `StrategyRegistry`, стратегії `seed_list` і `recursive`, API `collector.v1` |
| WP-03 | `sitemap` (+index, .gz), `feed` (RSS/Atom), `listing` (категорії, пагінація, пошук), `url_template`, `api_feed`; експортує `STRATEGIES` з `strategies/discovery/__init__.py` |
| — | `llm_explore` у v1 **не реалізується колектором**: реєстр стратегій повертає `supported: false` (`POST /v1/rules/validations`), збір із такою стратегією не стартує (`validation_failed`). LLM-дослідження джерела виконує onboarding асистента (WP-11, `assistant.v1`) і перетворює знахідки на звичайні стратегії в запропонованих правилах |

## Правила

1. Стратегія **не робить HTTP-запитів сама** — лише `ctx.fetch()`. Це гарантує, що robots.txt,
   межі домену, `exclude`, ліміти частоти й розміру діють для всіх стратегій однаково.
2. Стратегія **пропонує** `DiscoveredUrl`; ядро нормалізує, перевіряє scope/exclude/robots,
   дедуплікує (ключ — канонічний URL, `dedup` у правилах), обмежує глибину й розмір черги,
   упорядковує за пріоритетом (`priorities` правил + `priority` стратегії + `priority` кандидата).
3. `kind="navigation"` — сторінка потрібна лише для пошуку (sitemap, стрічка, сторінка списку,
   сторінка API); ядро не видає її як Material. `kind="material"` — кандидат у матеріали.
4. Комбінування: ядро викликає `on_fetched()` **усіх** стратегій для кожного отриманого ресурсу.
   Так `recursive` переходить за посиланнями зі сторінок, знайдених `sitemap`, а `listing` може
   реагувати на сторінки категорій, знайдені рекурсією.
5. Глибина: seeds мають `depth=0`; кандидат із `on_fetched` отримує `depth = resource.depth + 1`.
   `limits.crawl.max_depth` (ефективний, з урахуванням `limits` стратегії) застосовує ядро.
6. Стан: після кожної порції ядро зберігає `snapshot()` усіх стратегій разом із чергою; після
   рестарту викликає `restore()` і продовжує (критерій WP-02 «після kill обхід продовжується»).
7. Помилки мережі й HTTP ядро фіксує в `/v1/collections/{id}/errors`; `FetchRejected` —
   нормальна ситуація (стратегія пропускає URL), а не аварія стратегії.
8. Ліміти не зашиваються: усі числа — з `ctx.limits` або конфігурації стратегії.

## Очікувані перевірки на testsite (WP-01 `tests/fixtures/testsite/`)

- Кожна стратегія окремо знаходить очікуваний набір URL; у комбінації з `recursive` — об'єднання без дублів.
- Цикли посилань не зациклюють обхід; зовнішні посилання не завантажуються; `robots.txt` дотримано.
- `sitemap` читає index і `.gz`; `feed` — RSS і Atom; `listing` — пагінацію `rel=next` і параметром; `url_template` зупиняється після N поспіль 404.
