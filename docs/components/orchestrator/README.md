# Orchestrator

Orchestrator зберігає джерела й завдання, запускає їх вручну або за розкладом і проводить кожен матеріал ланцюжком етапів: отримує матеріали від колектора через `collector.v1` і викликає обробники через `handler.v1`. Стан запусків і черга етапів лежать у власній базі PostgreSQL; іншої черги чи брокера немає.

Код — [services/orchestrator](../../../services/orchestrator/), API — `orchestrator.v1` ([контракт](../../../contracts/openapi/orchestrator.v1.yaml), [довідник](reference/api/README.md)).

## Призначення й межі

Orchestrator відповідає за:

- **джерела й завдання** — CRUD з `ETag`/`If-Match`, перевірка конфігурації завдання (DAG етапів, умови, прив'язки, розклад);
- **запуски** — ручні, за розкладом (`once`, `cron`, `interval`) і повторну обробку збережених RAW; правила перекриття запусків `skip`, `queue`, `allow`;
- **чергу елементів етапів** — у PostgreSQL з lease (`SELECT … FOR UPDATE SKIP LOCKED`), повторами за `retryable`, ключем доставки `delivery_key` і відновленням після збою воркера;
- **підтвердження курсорів колектора** — сторінку матеріалів підтверджено лише після того, як її елементи записано в базу;
- **реєстр підключень** — документи підключень лише з `secret_refs`, синхронізація з виконавцями;
- **ліміти платформи** — документ рівня `platform` і злиття `platform → source → task → stage → request`;
- **активації версій пакетів** у етапах і відкат, з аудитом;
- **групи проблем** і **невідомі матеріали**, опцію «Передавати в LLM невідомі сторінки»;
- **простежуваність** — матеріал → етап → результат → версія пакета.

Orchestrator не отримує сторінки сам, не виконує код екстракторів, не пише результати в сховища й не викликає LLM-провайдерів: це роблять виконавці (executors) — колектори й обробники. Він не читає таблиць інших сервісів, лише їхні API. Вміст матеріалів не зберігається довгостроково: постійно лишаються ідентифікатори й посилання, а вхід обробника тримається в черзі лише до завершення елемента (деталі — [власні дані](internals.md#власні-дані)).

## Тип і автономність

| Властивість | Значення |
|---|---|
| Тип модуля | координація |
| Самостійний запуск | так: API, черга й розклади працюють лише з PostgreSQL |
| Корисна робота | потребує виконавців: колектора для збору й обробників для етапів |
| Обов'язкові залежності | PostgreSQL |
| Опційні залежності | колектори, обробники (Storage, Handler Runtime, LLM gateway), Registry, Storage для читання RAW |
| Хто від нього залежить | Admin UI; Assistant — лише для автоматичної активації |

Колектори й обробники від Orchestrator не залежать: їх можна викликати напряму. Orchestrator лише поєднує їх у завдання. Без виконавців API приймає джерела й завдання, але запуск не просуне матеріали далі — наслідки в [залежностях](dependencies.md#поведінка-без-виконавців).

## Основні поняття

| Поняття | Значення в Orchestrator |
|---|---|
| Джерело (`Source`) | Сайт або канал: тип, адреса, правила колектора за замовчуванням, ліміти, політика змін, прапорець невідомих сторінок |
| Завдання (`TaskConfig`) | Вхід (джерело, явні URL або збережені RAW), етапи, розклад, повтори, ліміти |
| Етап | `collect` — рівно один на завдання; `handler` — виклик пакета обробника точної версії |
| Ребро (`inputs[]`) | Звідки етап бере елементи: `select` = `output`, `input_material`, `problems`, `unmatched_materials`; умова `when` |
| Прив'язка (`bindings`) | До яких матеріалів застосовувати етап: розділи, шаблони URL, типи вмісту |
| Запуск (run) | Виконання завдання зі знімком конфігурації й ефективних лімітів; водночас асинхронний `Job` з `kind: run` |
| Елемент етапу (item) | Один виклик обробника для одного входу; одиниця черги з lease |
| Виконавець (executor) | Сервіс, який Orchestrator викликає: колектор, обробник, читання Storage, Registry, LLM gateway, Assistant |

## Сценарії

- **Збір каталогу з розгалуженням** — колектор → збереження RAW і паралельно екстрактор → збереження сутностей; проблемні результати → етап LLM. Приклад конфігурації — [task-catalog.json](../../../contracts/examples/openapi/task-catalog.json).
- **Періодична перевірка цін** — окреме завдання з явними URL і розкладом `interval` ([task-price-check.json](../../../contracts/examples/openapi/task-price-check.json)).
- **Скасування й повторна обробка** — `POST /v1/runs/{run_id}/cancel`, `POST /v1/reprocessing` зі збереженими RAW.
- **Вдосконалення екстрактора** — групи проблем із прикладами, нова версія пакета, активація або відкат у етапі.
- **Стороння система** — керує джерелами, завданнями й запусками лише через `orchestrator.v1` ([інтеграція](integration.md)).
