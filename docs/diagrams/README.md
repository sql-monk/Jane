## Файли діаграми

Кожна діаграма — три файли в `docs/diagrams/<розділ>/`:

| Файл | Призначення |
|---|---|
| `<назва>.drawio` | єдине редаговане джерело: справжні вузли, ребра й текст |
| `<назва>.light.png` | експорт для світлої теми, прозорий фон |
| `<назва>.dark.png` | експорт для темної теми з того самого джерела, прозорий фон |

PNG не редагуються вручну. Після зміни джерела обидва PNG експортуються заново, а [checksums.json](checksums.json) оновлюється: він зберігає SHA-256 джерела й обох PNG для кожної діаграми (ключ — `<розділ>/<назва>`).

## Стиль

Зразок — [platform/composition.drawio](platform/composition.drawio).

- Підписи без HTML (`html=0`); перенос рядка в підписі — символ нового рядка (`&#xa;` у XML), не тег `br`.
- Кольори, різні для тем, записуються як `light-dark(#світлий,#темний)`; експорт обирає значення за темою.
- Кольори вузлів за роллю: координація — бузковий, колектори — синій, обробники — зелений, репозиторій — помаранчевий, клієнти — сірий, зовнішні системи — білий або темний фон. Зміст має читатися й без кольору.
- Лінії розрізняють: API-виклик — суцільна, опційна залежність — штрих, звернення до зовнішньої системи або дані — пунктир. Якщо стилів кілька, діаграма має легенду.
- Логічний потік даних не видається за прямий виклик: між колектором і обробником стрілка потоку не означає HTTP-виклику — етапи викликає Orchestrator.

## Команди

Команди виконуються з кореня репозиторію; скрипт [scripts/docs_diagrams.py](../../scripts/docs_diagrams.py) сам встановлює свою залежність (Pillow) через `uv run --script`.

Перевірка джерел без експорту — для автора діаграми:

```powershell
uv run --script scripts/docs_diagrams.py lint docs/diagrams/platform/context.drawio
```

```text
ok   platform/context
```

Експорт обох PNG і оновлення контрольних сум (без аргументів — усі джерела):

```powershell
uv run --script scripts/docs_diagrams.py export docs/diagrams/platform/context.drawio
```

Повна перевірка без draw.io — розбір джерел, ребра вказують на наявні вузли, немає HTML-підписів; обидва PNG мають RGBA, прозорий фон, видимий вміст і однаковий розмір; контрольні суми збігаються:

```powershell
uv run --script scripts/docs_diagrams.py check
```

Експорт потребує draw.io desktop: шлях задає `JANE_DRAWIO`, інакше `C:\Program Files\draw.io\draw.io.exe` на Windows або `drawio` у `PATH` на Linux (без дисплея — під `xvfb-run`). Тайм-аут одного експорту — `JANE_DRAWIO_TIMEOUT_S` (типово 90 с). Запускайте експорт в одному процесі: draw.io не можна запускати паралельно.

У цій документації виконано лише `lint` для діаграм розділу `platform/`; експорт PNG і `check` виконує координатор.

## Вставка в сторінку

Шляхи відносні до сторінки. Світла й темна версії йдуть парою: переглядач, що підтримує теми (GitHub), показує відповідну; поруч — посилання на обидва PNG і джерело.

```text
![Короткий опис схеми](../diagrams/<розділ>/<назва>.light.png#gh-light-mode-only)
![Короткий опис схеми](../diagrams/<розділ>/<назва>.dark.png#gh-dark-mode-only)

Зображення для теми: [світле](../diagrams/<розділ>/<назва>.light.png), [темне](../diagrams/<розділ>/<назва>.dark.png); джерело — [<назва>.drawio](../diagrams/<розділ>/<назва>.drawio).
```

Інші переглядачі Markdown можуть показати обидва PNG поспіль.

## Розділи

| Каталог | Діаграми |
|---|---|
| `platform/` | платформа загалом — таблиця нижче |
| `admin/`, `user-guide/` | Admin UI і сценарії оператора |
| `web-collector/`, `telegram-collector/` | колектори |
| `storage/`, `handler-runtime/` | обробники |
| `registry/`, `packages/` | Registry і пакети обробників |
| `extractor-sdk/` | SDK екстракторів |

Діаграми інших модулів додаються в каталог `docs/diagrams/<модуль>/` за тими самими правилами.
