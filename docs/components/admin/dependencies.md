## Середовище збирання

| Залежність | Версія | Обов'язковість | Для чого |
|---|---|---|---|
| Node.js | 24 (`.node-version`) | обов'язкова для збирання й dev-сервера | Vite, скрипти `web/admin/scripts/*.mjs` |
| pnpm | `packageManager: pnpm@11.27.1`; запуск через `corepack pnpm` | обов'язкова | встановлення залежностей за lock-файлом |
| uv | будь-яка з підтримкою `uv run` для скриптів | лише для моків і e2e на моках | `contracts/tools/mock.py` (Python ≥ 3.12, `pyyaml`) |
| Chromium для Playwright | завантажує Playwright | лише для `e2e` | браузерні тести |

Зібраній адмінці Node.js не потрібен: це статичні файли, які віддає будь-який вебсервер.

`pnpm-workspace.yaml` задає `pmOnFail: warn`: якщо corepack запускає іншу версію pnpm, ніж у `packageManager`, команда виконується з попередженням `This project is configured to use 11.27.1 of pnpm`. Перевірка на ревізії `48389a3` пройшла з pnpm 12.8.1.

## Сервіси під час роботи

Адмінка звертається до API через reverse proxy за адресою `<api_base>/<сервіс>/v1/...` ([configuration.md](configuration.md#configjson)). Сумісні версії — API `/v1` поточних контрактів; типи клієнтів згенеровано з [contracts/openapi](../../../contracts/openapi/) тієї самої ревізії.

| Сервіс | Контракт | Обов'язковість |
|---|---|---|
| Orchestrator | `orchestrator.v1` | потрібен майже всім сторінкам: джерела, завдання, запуски, проблеми, підключення, ліміти, аудит |
| Registry | `registry.v1` | пакети, редактори, версії етапів |
| Storage | `storage.v1` | матеріали, результати, приклади проблем |
| LLM gateway | `llm.v1` | сторінка LLM, витрати на «Огляді» |
| Handler Runtime | `handler.v1` | тести версій пакета |
| Assistant | `assistant.v1` | асистент, вдосконалення на сторінці проблем |
| Колектор (Web Collector) | `collector.v1` | вкладка «Помилки колектора» запуску |
| Виконавець за ім'ям | `handler.v1` | кнопка «Перевірити» підключення |
| Постачальник ідентичності | OIDC | лише за `auth.mode = "oidc"` |

Детальна карта сторінок і операцій — [integration.md](integration.md#сторінки-та-api).

## Поведінка за недоступності

| Що недоступне | Що бачить оператор |
|---|---|
| `config.json` (не `200`) | адмінка стартує з типовими значеннями ([configuration.md](configuration.md#типові-значення)) |
| `config.json` з неповним `auth.mode = "oidc"` | замість адмінки — повідомлення «Не вдалося завантажити config.json» |
| сервіс не відповідає (мережева помилка) | на сторінках цього сервісу — блок «Помилка Запит не виконано (`upstream_unavailable`, HTTP 502)»; інші сторінки працюють |
| сервіс повертає `5xx` | той самий блок із кодом із `problem+json` сервісу або `upstream_unavailable`, якщо тіло не `problem+json` |
| ключ або токен (`401`) | банер «Сесія недійсна або прострочена (401)» з посиланням «Увійти знову» |
| права (`403`) | блок помилки з кодом `forbidden` на операції |
| постачальник OIDC | помилка на сторінці входу після «Увійти через IdP» |
| моки під час `pnpm dev` | запити `/api/*` завершуються помилкою proxy Vite; сторінки показують `upstream_unavailable` |

Запити з помилкою повторюються один раз (`retry: 1` у `QueryClient`); дії користувача (збереження, запуск) не повторюються автоматично.
