# Підключення джерела

Джерело — сайт або Telegram-канал, з якого збираються матеріали. Його можна описати вручну на сторінці «Джерела» або доручити асистенту: він знайде джерело за назвою, дослідить вибірку матеріалів і запропонує варіанти збору з правилами колектора й екстракторами.

## Список джерел

Сторінка «Джерела» (`/sources`) показує таблицю: ідентифікатор, назва, тип, адреса, правила колектора (`пакет@версія`), «Невідомі сторінки → LLM» і кнопку «Завдання джерела». Фільтри — «Пошук у завантажених джерелах» і «Тип джерела» («Усі джерела», «Вебсайти», «Telegram»).

## Нове джерело вручну

Передумови:

- відомі адреса сайту або ім'я чи ідентифікатор Telegram-каналу;
- для обходу сайту потрібен пакет правил колектора (`collector-rules`) — його створює асистент або ви на сторінці «Пакети» ([пакети й версії](packages.md)). Без правил завдання може збирати явний перелік URL.

Кроки:

1. На сторінці «Джерела» натисніть «Нове джерело».
2. Заповніть поля:

   | Поле | Значення |
   |---|---|
   | Ідентифікатор (source_id) | нижній регістр, цифри, `.`, `_`, `-`; після створення не змінюється |
   | Тип (kind) | `web` або `telegram` |
   | Назва, Опис | людська назва й опис |
   | URL | для `web` — адреса сайту |
   | Telegram username, Telegram channel id | для `telegram` — ім'я або ідентифікатор каналу |
   | Очікувані типи даних | через кому, наприклад `product, price` |
   | Версії від LLM (change_policy) | «ручне погодження», «автоактивація після перевірок» або «заборонено» |
   | Передавати в LLM невідомі сторінки | вмикає виклик LLM для матеріалів без обробника |

3. У розділі «Правила колектора (стратегії обходу)» вкажіть «Пакет правил (package_id)» і «Версія». Під полями з'явиться таблиця стратегій цієї версії й кнопка «Редагувати стратегії».
4. За потреби заповніть JSON-редактори «Ліміти рівня джерела» ([ліміти](limits.md)) і «Підключення (логічне ім'я → connection_id)», наприклад `{"results": "results-pg"}` ([сховища й LLM](connections-and-llm.md)).
5. Якщо під формою є список «Помилки форми», виправте вказані поля — кнопка неактивна, доки помилки є.
6. Натисніть «Створити джерело».

Очікуваний результат: адмінка переходить на сторінку «Джерело <source_id>», з'являється «Збережено». Внизу — «Ефективні ліміти джерела» з рівнем, звідки береться кожне значення.

Опція «Передавати в LLM невідомі сторінки» за замовчуванням вимкнена: без неї LLM для невідомих матеріалів не викликається. Завдання може перевизначити її («як у джерела», «увімкнено», «вимкнено»).

## Зміна й видалення джерела

1. Відкрийте джерело з таблиці.
2. Змініть поля й натисніть «Зберегти». Ідентифікатор змінити не можна.
3. Щоб видалити, натисніть «Видалити», за бажання вкажіть причину й підтвердіть «Видалити джерело».

Очікуваний результат: після збереження — «Збережено» й час «Оновлено …»; після видалення — повернення до списку. Якщо джерело змінив хтось інший після відкриття сторінки, збереження завершиться помилкою з кодом `precondition_failed` — перезавантажте сторінку й повторіть зміни. «Завдання джерела» відкриває список завдань, відфільтрований за цим джерелом.

## Підключення з асистентом

Передумови:

- запущено Assistant, LLM gateway з налаштованим провайдером, Registry, колектор і Handler Runtime;
- бюджет LLM дозволяє дослідження ([сховища й LLM](connections-and-llm.md#бюджети)).

Кроки:

1. Відкрийте «Асистент» (пункт меню, кнопка у верхній панелі, «Підключити через асистента» на «Джерелах» або «Підключити джерело» на «Огляді»). Вкладка «Підключення джерел».
2. Перегляньте блок «Ліміти дослідження»: поріг достатності вибірки, максимум сторінок вибірки, бюджет LLM асистента.
3. У блоці «Нове підключення» заповніть:

   | Поле | Значення |
   |---|---|
   | Назва або посилання | обов'язково: назва сайту чи каналу або точне посилання |
   | Тип джерела (необов'язково) | `web` або `telegram` |
   | Очікувані типи даних | через кому |
   | Бюджет дослідження, Валюта | межа витрат LLM на цю сесію |
   | Макс. сторінок вибірки | межа вибірки |
   | Поріг впевненості вибірки | більше 0 і не більше 1; порожньо — поріг асистента |
   | Дозволити автоматичну активацію | асистент може сам активувати прийнятий варіант, якщо дозволяє політика |
   | Правила обходу від користувача | необов'язковий фрагмент правил колектора у JSON |

4. Натисніть «Почати підключення».

Очікуваний результат: з'являється панель «Підключення джерела» зі станом job, а в таблиці «Сесії» — нова сесія. Сесія проходить стани `resolving`, `sampling`, `analyzing` і зупиняється на `proposals_ready`, `needs_disambiguation`, `insufficient_sample` або `failed`. Сторінка оновлюється сама, поки сесія активна. Після перезавантаження сесію можна знайти в таблиці «Сесії» або відкрити полем «Відкрити сесію за ідентифікатором».

Якщо стан `needs_disambiguation`, у сесії з'являється «Уточніть джерело» з кандидатами (назва, адреса, впевненість). Натисніть «Обрати» біля потрібного — дослідження продовжиться. Якщо `insufficient_sample` — вибірки замало для впевненого висновку; збільште «Макс. сторінок вибірки» чи бюджет і почніть нову сесію.

## Варіанти й прийняття

У стані `proposals_ready` сесія показує:

- повідомлення про вибірку: кількість матеріалів, типів і впевненість;
- «Аналіз»: тип джерела, способи обходу, типи матеріалів, поля сутностей з покриттям;
- картки варіантів: стратегії обходу, охоплення, запитів за запуск, вартість LLM на налаштування й за запуск, ризики, екстрактори (дія «прив'язати наявний», «адаптувати форк» або «створити новий», пакет, збіг, перевірка на прикладах) і правила колектора варіанта. Рекомендований варіант позначено «рекомендовано».

Кроки:

1. За бажання вкажіть «source_id для джерела» й увімкніть «Активувати одразу (якщо дозволяє політика)».
2. Натисніть «Прийняти варіант» на обраній картці.
3. Дочекайтеся завершення панелі «Застосування варіанта».

Очікуваний результат: у результаті — правила колектора, створені або прив'язані екстрактори зі звітами тестів і «Активовано: так» або «ні — створіть джерело й завдання з чернеток».

- Якщо варіант активовано — є посилання на створене джерело й завдання.
- Якщо ні — натисніть «Створити джерело з чернетки» й «Створити завдання «<назва>»». Після кожної дії з'являється посилання «Джерело створено» або «Завдання створено».

Далі перевірте нові версії пакетів ([пакети й версії](packages.md)) і завдання ([завдання й розклад](tasks.md)), а перший запуск зробіть у тестовому режимі ([запуск і спостереження](runs.md)).
