# Повні каталоги магазинів

Набір налаштовує збір усього публічного українського асортименту п’яти сайтів, зберігає товари й історію спостережень у PostgreSQL та продовжує великі обходи між запусками. Товари доступні в адміністративному інтерфейсі Jane через результати відповідного джерела.

## Джерела й властивості

| Сайт | Товари | Приклади властивостей | Пошук усього асортименту |
|---|---|---|---|
| Будинок іграшок | Іграшки, дитячі товари, транспорт | Бренд, вік, колір, розмір, вага | Повний український sitemap index |
| Епіцентр | Маркетплейс, дім, сад, ремонт та інші категорії | Продавець, бренд, матеріал, потужність, габарити | Актуальні українські sitemap магазинів і продавців |
| PROSTOR | Косметика, догляд, побутова хімія | Склад, об’єм, тип шкіри, призначення | Усі українські товарні URL sitemap |
| VARUS | Продукти, напої, побутові товари | Вага, об’єм, склад, харчова цінність, пакування | Динамічне дерево всіх категорій і брендів API |
| Yakaboo | Книги та інші товари магазину | ISBN, автор, видавництво, сторінки, мова, формат | Повний опублікований sitemap index, українські картки |

Конфігурації містяться в [sites/](sites/), екстрактори зі схемами й перевіреними прикладами — у [packages/](packages/). Відсутнє на сторінці значення пропускається; ціни не вигадуються. Регіональні чи російські дублікати карток відсіюються правилами URL.

## Розклад і продовження

Основний каталог запускається кожні 15 хвилин з `overlap: skip`. Один запуск читає до 400 сторінок; VARUS має бюджет 100 запитів API, кожен з яких повертає до 48 товарів. Непрочитані URL та незавершена навігація зберігаються у checkpoint і переходять до наступного запуску. Активна черга обмежена; її надлишок зберігається стисненим на диску. Відомі товари допускаються до повторного відвідування після 24 годин; пріоритет мають ще не прочитані товари.

Час оновлення конкретного товару визначає тривалість повного циклу. Для 118 580 карток при 400 сторінках кожні 15 хвилин первинний цикл потребує щонайменше близько 3 діб. Для багатомільйонного маркетплейсу він може тривати місяці. Розклад запусків не гарантує оновлення кожної ціни раз на добу. Дійсну свіжість показують час спостереження та історія сутності.

Старі окремі завдання `prices-*` переведені в ручний режим. Основний цикл отримує актуальні ціни разом із характеристиками й усуває конфлікт одночасних зборів одного джерела. Каталоги та історія цін постійно зберігаються через `results-pg`; стиснені перевірені знімки — у [catalogs/](catalogs/).

## Застосування до запущеної версії

Потрібні Docker, `uv`, запущена Jane з міжсервісними підключеннями та її локальний файл `.jane/stack-<project>.json`. Він містить локальну конфігурацію доступу і залишається поза Git. Для іншого checkout передайте шлях через `deploy_catalogs.py --state`; клієнтам налаштувань потрібен файл стану у власній `.jane/`.

```powershell
uv run --all-packages python examples/sites/setup_sites.py check bi epicentrk prostor varus yakaboo
pnpm --dir web/admin typecheck
pnpm --dir web/admin build
uv run --all-packages python examples/sites/deploy_catalogs.py --project jane-demo --build --publish-admin
uv run --all-packages python examples/sites/setup_sites.py apply --project jane-demo --reviewed-package-updates bi epicentrk prostor varus yakaboo
uv run --all-packages python examples/sites/catalog_status.py --project jane-demo
```

Розгортання оновлює Web Collector і Registry для нових правил API та налаштовує паралельну обробку. Томам і даним відповідає існуючий compose project. Паралельність задається `--workers` і `--sandboxes`, типово 12 і 8; швидкість сайтів лишається обмеженою їхніми правилами та одним запитом за секунду на хост.

`--reviewed-package-updates` означає разовий дозвіл оператора на перевірені нові версії пакетів. Перед публікацією повторно перевіряються вибрані пакети; для пакета із забороною LLM-змін дозвіл діє лише під час одного upload і відновлюється у `finally`, навіть при помилці. Походження `created_by: llm` лишається правдивим. Без цього явного параметра заборонений upload відхиляється. Уже опубліковані версії читаються й звіряються за дайджестом без повторного upload.

Після зміни схеми правил перегенеруйте й опублікуйте адміністративний клієнт:

```powershell
pnpm --dir web/admin gen:api
pnpm --dir web/admin typecheck
pnpm --dir web/admin build
```

`deploy_catalogs.py --publish-admin` копіює `dist` у незмінний реліз `.jane/releases/admin-<digest>`, оновлює proxy та зберігає адресу релізу в локальному файлі стану стеку. Порти беруться з наявного стану й не перевибираються Docker. Локальна збірка без цієї публікації не змінює запущений proxy.

## Перевірка результату

`catalog_status.py` читає всі вже збережені товари через Storage API, перевіряє схеми пакетів цього сайту, числові ціни та приклади історії, зберігає `.json.gz` для кожного джерела і `status.json`. Початкові знімки прямо позначають незавершений повний обхід.

Охоплення перевіряється окремо: невідвідані URL, `continuation_pending`, помилки HTTP та лічильники обрізання sitemap. Ненульові `entries_over_limit`, `truncated_documents`, `dropped_frontier_full`, `partitions_over_limit` або `partitions_over_depth` потребують виправлення лімітів чи правил. `spooled_frontier_full` означає збережений надлишок черги, а не втрачені URL. API `/v1/states/{source_id}` показує збережену чергу, а `/v1/collections/{collection_id}` — стан конкретної частини обходу.

Застарілий `/sitemap.xml` Епіцентру повертає 410 для частини карт; правила використовують актуальні sitemap із `robots.txt`. VARUS обмежує широкий список приблизно 10 тисячами позицій і повторює останню сторінку; дерево категорій і брендів обходиться окремими розділами до повтору товарних URL.

```powershell
uv run --all-packages python examples/sites/setup_sites.py verify --project jane-demo bi epicentrk prostor varus yakaboo
uv run --all-packages python examples/sites/export_sites.py --project jane-demo --history product
```

Перевірка `verify` містить мінімальні критерії початкового набору товарів. Завершення всього асортименту підтверджується інвентаризацією й порожньою чергою після повного discovery.
