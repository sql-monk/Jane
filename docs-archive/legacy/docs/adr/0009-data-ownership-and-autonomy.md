# ADR-0009. Власність даних, відсутність спільної БД, автономність

**Статус:** прийнято (WP-00, 2026-09-27)

## Контекст
ТЗ §4: сервіси не звертаються до внутрішніх таблиць інших сервісів; колектор і екстрактор
використовуються окремо; кожен компонент можна використати без оркестратора. ТЗ §5: колектори й
екстрактори не зберігають бізнес-результати в БД. PostgreSQL — сховище оркестратора, не
обов'язкова залежність кожного компонента. Критерій «Готово» WP-00: немає спільної БД і немає
залежності автономних компонентів (колектори, runtime, збереження, репозиторій, LLM) від
оркестратора.

## Рішення
1. Кожен сервіс має **власне сховище** (власна база/роль або SQLite/файли), доступне лише йому.
   Повна карта — [`contracts/docs/data-ownership.md`](../../contracts/docs/data-ownership.md).
2. **Бізнес-результати** пишуть лише обробники збереження в цільові сховища користувача.
   Колектори, runtime, llm бізнес-результатів не зберігають (лише службовий стан і кеш ідемпотентності).
3. Оркестратор зберігає лише конфігурацію, стан виконання й **ідентифікатори** для простежуваності,
   не вміст.
4. **Автономність від оркестратора** забезпечується контрактами:
   - колектор: правила inline/файл або з registry; матеріали через pull-API;
   - runtime/storage/llm: пакет з registry **або** архів у запиті; підключення — з власної
     конфігурації або синхронізовані; ліміти — у запиті або власні типові;
   - registry: залежить лише від власної БД і blob-сховища.
   Жоден із цих API не має операцій чи полів, що вимагають виклику оркестратора.
5. Асистент (WP-11) і адмінка (WP-12) — інтеграційні компоненти; асистент звертається до
   оркестратора лише для автоактивації за дозволом користувача.

## Наслідки
- Кожен сервіс масштабується й розгортається окремо; стан кількох екземплярів — у його сховищі.
- Потрібні API для всього, що бачить адмінка (storage.v1 для результатів, collector errors тощо).
- Звіти між сервісами (витрати, проблеми) агрегуються через API, а не SQL-з'єднаннями.

## Альтернативи
- **Одна спільна БД зі схемами на сервіс** — дешевше в dev, але зв'язує міграції й масштабування,
  спокушає до крос-схемних запитів; відхилено. (Один сервер PostgreSQL з окремими базами й ролями в dev
  дозволено — це не спільна БД.)
- **Оркестратор як джерело конфігурації для всіх** (сервіси тягнуть налаштування з нього) — робить
  оркестратор обов'язковою залежністю.
