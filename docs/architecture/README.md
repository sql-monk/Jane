- **Оператор** працює через Admin UI, який викликає API сервісів через proxy.
- **Сторонній застосунок** може викликати будь-який модуль напряму, без Orchestrator.
- **Зовнішні системи:** джерела (сайти, Telegram), цільові сховища результатів, провайдери LLM і контейнерний рушій для пісочниць екстракторів.

## Принципи будови

- **Orchestrator керує виконанням.** Він викликає колектор, отримує матеріали й сам передає їх кожному обробнику. Колектори й обробники одне одного не викликають — [виконання завдання](task-execution.md).
- **Кожен модуль володіє своїми даними.** Спільної бази немає; дані іншого модуля доступні лише через його API — [власність даних](data-ownership.md).
- **Колектори й екстрактори не зберігають бізнес-результати.** Збереження — окремий етап Storage, тому сховище змінюється без зміни коду колектора чи екстрактора.
- **Пакет замість коду в сервісі.** Екстрактори, правила колекторів, LLM-обробники й адаптери збереження описуються пакетами з маніфестом і версією; етап завдання посилається на версію й дайджест.
- **Ліміти — конфігурація.** Паралельність, частота, глибина, тайм-аути, повтори, розміри й бюджети задаються на рівнях платформи, джерела, завдання й етапу з безпечними типовими значеннями.
- **Код сайтів — дані.** Вміст сторінок і повідомлень не є інструкціями для LLM; код екстракторів виконується в ізольованій пісочниці — [безпека](security.md).

## Автономність модулів

Кожен модуль запускається окремо з власною конфігурацією й API. Orchestrator не є обов'язковою залежністю жодного модуля, крім Assistant для автоматичної активації.

| Модуль | Без Orchestrator | Що замінює відсутній сусід |
|---|---|---|
| Web Collector, Telegram Collector | так | правила колектора передаються в запиті або з локального файла замість Registry |
| Handler Runtime | так | пакет передається архівом у запиті замість Registry |
| Storage | так | стандартні пакети `jane.storage-*` вбудовані в сервіс |
| LLM gateway | так | LLM-пакет передається архівом; провайдер `fake` замість реального |
| Registry | так | без профілів Handler Runtime (`JANE_REGISTRY_RUNTIME_PROFILES`) відхиляє версії екстракторів із `runtime_profile` кодом `dependency_not_allowed`; інші види пакетів публікуються |
| Assistant | частково | без своїх обов'язкових сусідів повертає `upstream_unavailable` для функцій, яким вони потрібні |
| Orchestrator | — | потребує власної БД і виконавців, які він поєднує |

Обов'язкові й опційні залежності кожного модуля — [каталог модулів](../components/README.md) і сторінка `dependencies.md` модуля.

## Композиція й заміна модулів

- **У Jane** модулі поєднує Orchestrator за списком виконавців (`JANE_ORCHESTRATOR_EXECUTORS` або файл `executors_file`). Виконавець має роль (`collector`, `handler`, `storage_read`, `registry`, `llm`, `assistant`), адресу й можливості (`capabilities`). Обробник для етапу Orchestrator обирає за шаблоном `package_id`, видом пакета (`handler_kinds`) або позначкою `default`.
- **У сторонньому застосунку** модуль викликається напряму за його контрактом; приклад — [швидкий старт Web Collector](../../README.md#модуль-окремо-web-collector) і `integration.md` модуля.
- **Заміна сумісною реалізацією.** Новий колектор або обробник реалізує `collector.v1` або `handler.v1` і реєструється в Orchestrator як ще один виконавець; ядро Orchestrator не змінюється. Сумісність перевіряють контрактні тести (`just contract`) і мок-сервер із прикладів контракту (`just contracts-mock <api>`). Новий адаптер Storage проходить набір сумісності — [storage-adapter.md](../../contracts/docs/storage-adapter.md).

## Спільні конвенції API

| Конвенція | Суть |
|---|---|
| Версія в шляху | усі операції під `/v1/...`; несумісна зміна — нова версія контракту |
| Помилки | `application/problem+json` з `code` і `retryable` — [модель помилок](../../contracts/docs/errors.md) |
| Ідемпотентність | операції зі зміною стану приймають `Idempotency-Key`; повтор повертає збережену відповідь із `Idempotency-Replayed: true` |
| Тривалі операції | `202 Accepted` з Job і `Location: /v1/jobs/{job_id}`; стан — `GET /v1/jobs/{job_id}`, скасування — `POST /v1/jobs/{job_id}/cancel` |
| Великі матеріали | вміст до `limits.transfer.inline_max_bytes` — у тілі, більший — посиланням `ContentRef` |
| Пагінація | курсорна: `limit` і `cursor`, у відповіді `items` і `next_cursor` |
| Службові точки | `GET /v1/health` без ключа, `GET /v1/info` з будь-яким дійсним ключем, `GET /metrics` у форматі Prometheus |
| Автентифікація | `Authorization: Bearer <ключ>` і дозволи (scopes) операцій — [безпека](security.md) |
