## Результат

- Спільний [UnsavedChangesProvider](../../web/admin/src/components/UnsavedChanges.tsx) захищає SPA-посилання, програмні переходи, локальну зміну контексту та нативні Back/Forward. Діалог пропонує залишитися, відкинути або зберегти перед переходом. Reload і вихід із вкладки використовують браузерне попередження `beforeunload`. Помилка збереження та невалідна форма залишають чернетку на місці. Listener встановлюється через layout effect перед батьківським BrowserRouter; інакше нативний Back встигав розмонтувати форму.
- Захист підключений у [джерелах](../../web/admin/src/pages/SourcesPage.tsx), [завданнях](../../web/admin/src/pages/TasksPage.tsx), [правилах](../../web/admin/src/pages/RulesEditorPage.tsx) та [редакторі пакета](../../web/admin/src/pages/PackageEditorPage.tsx). Чернетки зберігаються між вкладками завдання та файлами пакета. Є видимий стан змін і закріплені дії збереження. Під час запиту поля, JSON і код блокуються, щоб відповідь на старий знімок не позначила нові правки збереженими.
- [Валідація контрактних схем](../../web/admin/src/lib/schema.ts) пояснює помилки українською, називає поле і прибирає зайвий шум умовних схем. Початкові нові форми не показують помилок; невдала спроба збереження виділяє поля через `aria-invalid` і пояснення. [JSON-редактор](../../web/admin/src/components/JsonEditor.tsx) показує технічні подробиці в розкривному блоці після редагування.
- [EntityPicker](../../web/admin/src/components/EntityPicker.tsx) дозволяє знайти джерело за реальною назвою або адресою з API, обрати його зі збігів і бачити точний ідентифікатор. Опис джерела став багаторядковим, додаткові JSON конфігурації згорнуті.
- У [ChainEditor](../../web/admin/src/components/ChainEditor.tsx) пакет і версія змінюються верхніми селекторами; дубльовані редаговані `handler` та `collector.rules` вилучені з гріда. Дайджест і посилання доступні в додатковому блоці лише для перегляду. Вибір «Правила джерела» показує фактичний пакет і версію обраного джерела.
- [PropertyGrid](../../web/admin/src/components/PropertyGrid.tsx) використовує списки допустимих значень із контракту та фактичної схеми параметрів: режим колектора, оператори умов, інші enum, зокрема вкладені. Підключення обираються через спільний ConnectionPicker. Невідоме збережене значення відображається явно, без тихої заміни. Вкладені об’єкти, масиви, типи, хибні значення, чернетки чисел та зміна порядку збережені.
- [Мобільний грід](../../web/admin/src/chain-editor.css) на 390 px перетворюється на картки з підписами «Назва / Тип / Значення»; на desktop лишаються три колонки. Перевірено фактичне редагування вкладеного масиву і перестановку його елементів у світлій та темній темах.
- Завдання містить переходи до фактичних сховищ результатів: перевіряється `manifest.kind=storage`, прив’язка `connections.target` і вихід попереднього handler-етапу. Фільтр `scope` передається лише з прямого `params.scope`; `source_id` не перетворюється на scope. UI пояснює, що connection може містити результати інших завдань. Якщо сховище не визначено або метадані недоступні, це показано явно; загальний каталог залишається доступним.

### Інтерфейс спільного захисту

Provider розміщено координатором усередині BrowserRouter навколо Routes. Для форми використовується:

```typescript
const guard = useUnsavedChanges({
  dirty,
  label: "Назва форми",
  onSave: async () => {
    if (!valid) return false;
    await save();
    return true;
  },
  onDiscard: discard,
});
// Перед переходом після успішного збереження:
guard.markSaved();
// Перед локальною зміною контексту, яка замінить форму:
guard.confirmChange(changeContext);
```

Батьківський компонент може застосувати `useConfirmUnsavedChange()`, коли dirty-форма живе в його дочірній вкладці. Для SPA-навігації через Router окремий виклик не потрібен. API Provider сумісний із чинним BrowserRouter, без переходу на data router.

## Відомі обмеження

Збереження чернеток діє протягом життя форми й дозволяє керовано залишити сторінку. Після погодженого reload/виходу браузер не відновлює чернетку з диска. Текст системного `beforeunload` задає браузер. Код захисту використовує чинний BrowserRouter NavigationContext і покритий StrictMode та справжнім Chromium.

Пошук EntityPicker працює серед завантажених сторінок, із явним завантаженням наступних; можна ввести точний id для сумісності з чинними сценаріями. Робочий сервіс залишається остаточним валідатором існування джерела та пакетів. Схема параметрів пакета надає enum/опис, але остаточну package validation виконує сервіс.

Посилання завдання показують сховища збереженої конфігурації. У наявному storage API connection/scope не доводять належність кожної сутності одному запуску чи джерелу; UI цього не стверджує. Відсутній явний scope не підміняється source_id.

## Неперевірені інтеграції

Нові сценарії цього WP виконано на контрактних моках; на робочому стеку не перевірено. Створення й реальний запуск ланцюжка, зовнішні адаптери, повний CI, deployment і main — наступне приймання координатора WP-32. Worker не виконував live writes, push, merge main чи deployment.

Імена полів і значення підключень пояснено над грідом; потрібні імена мають також доступний опис у відповідних рядках. [ChainEditor](../../web/admin/src/components/ChainEditor.tsx) перевіряє всі handler-етапи, включно з невибраними. Відсутнє або порожнє обов’язкове підключення показує етап і точне логічне ім’я та через чинний `onValidityChange` блокує збереження і перевірку під час редагування ланцюжка. Редагування структури залишається доступним, щоб користувач виправив поле. `optional=true` не блокує форму. Поки маніфести завантажуються, показано стан перевірки, без передчасних помилок відсутніх полів. Відсутній маніфест чи збій отримання не підмінюються вигаданими вимогами: показано недоступність та потребу перевірки в оркестраторі. Успадкування правил збору й наявні значення конфігурації не змінено.

Запити точних версій мають спільний кеш для перевірки ланцюжка та допомоги вибраного етапу; однакові версії в ланцюжку не дублюються. Схема параметрів завантажується окремо, тому її відсутність не втрачає вимоги підключень із маніфесту.
