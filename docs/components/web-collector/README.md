# Web Collector

Web Collector отримує вебсторінки та інші вебматеріали за правилами джерела й повертає їх із метаданими через спільний API колекторів `collector.v1`. Тип модуля — колектор; працює окремо, без Orchestrator, Registry і обробників.

## Призначення й межі

| Відповідає за | Не відповідає за |
|---|---|
| пошук URL за стратегіями та їх комбінацією | збереження RAW і результатів — це етап обробника Storage |
| межі обходу, `robots.txt`, дедуплікацію, глибину, пріоритети | витягування сутностей — це екстрактори в Handler Runtime |
| ліміти на хост, повтори, переадресації, розміри | розклади й ланцюжки етапів — це Orchestrator |
| буфер виданих матеріалів із підтвердженням курсором | дослідження нового джерела моделлю — це Assistant |
| власний стан обходу й історію URL у SQLite | |

Колектор не зберігає бізнес-результатів: матеріал залишається в його буфері лише до підтвердження отримувачем.

## Можливості

- **Разове отримання** — `POST /v1/fetches` повертає один матеріал синхронно.
- **Збір** — `POST /v1/collections` запускає асинхронне завдання (job); матеріали читаються сторінками з курсором, помилки URL — окремим списком.
- **Стратегії пошуку** — `seed_list`, `recursive`, `sitemap`, `feed`, `listing`, `url_template`, `api_feed`; кілька стратегій зливаються в одну чергу з дедуплікацією.
- **Повторні збори** — `mode: incremental` зі спільним `state_key`: умовні запити, `revisit`, `lastmod`.
- **Рендеринг JavaScript** — `fetch.render_js` у headless Chromium (опційний extra `render`).
- **Кілька екземплярів** — на одному вузлі зі спільним каталогом стану: оренда (lease) збору, спільні ліміти хоста.
- **Кероване підключення** `kind=http` — автентифікація до сайту без секретів у правилах.

## Автономність

Мінімальне середовище — Python 3.12, uv і доступ до сайтів. Правила передаються в запиті (inline), з локального каталогу `RULES_DIR` або з Registry; стан — файл SQLite у `STATE_DIR`. Жодних звернень до Orchestrator немає. Повний перелік — [dependencies.md](dependencies.md).

## Обмеження

- **Розбіжність із ТЗ.** ТЗ (§6, §13.1 п. 1) перелічує «автоматичне дослідження джерела за допомогою LLM» серед способів пошуку. Колектор стратегію `llm_explore` не виконує: `POST /v1/rules/validations` відповідає `supported: false`, збір із нею відхиляється `validation_failed`. Дослідження джерела виконує Assistant і перетворює знахідки на звичайні стратегії.
- **Масштабування** — кілька екземплярів узгоджуються лише через спільний файл SQLite на одному вузлі. Екземпляри з різними `STATE_DIR` не координують ліміти хоста й не бачать зборів одне одного.
- **Рендеринг** перевірено на Windows 11 з Chromium, встановленим Playwright; без браузера URL з `render_js` завершуються `not_implemented`.
- Інструкції перевірено на Windows 11 (ревізія `48389a3`); на Linux не перевірялися.
