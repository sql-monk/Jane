# Storage

Storage — обробник збереження Jane. Він приймає від Orchestrator або стороннього застосунку RAW-матеріали, сутності й документи результатів, записує їх у вибране сховище через адаптер і віддає збережене через API читання. Код — [services/storage](../../../services/storage/), пакет `jane-storage` версії `0.1.0`, Python 3.12+; адаптери — окремі пакети в [services/storage/adapters](../../../services/storage/adapters/).

## Межі відповідальності

| Тип | Обробник (`handler_kind: storage`) |
|---|---|
| Робить | Записує RAW, сутності з історією й документи результатів; дедуплікує повторні доставки; враховує порядок спостережень; віддає збережене через `storage.v1` |
| Не робить | Не отримує матеріали з джерел, не витягує сутності, не розкладає завдання; не зберігає бізнес-дані у власній базі — лише в цільових сховищах користувача |
| API запису | `handler.v1` — спільний контракт обробників: `POST /v1/invocations`, підключення, тести пакета, job |
| API читання | `storage.v1` — сутності, історія, об'єкти й їхній вміст |
| Сховища | Адаптери `filesystem`, `postgresql`, `sqlserver`, `mongodb`, `minio`, `s3` |
| Споживачі | Orchestrator (етап збереження, повторна обробка), Assistant і Admin UI (читання), сторонні застосунки |

Семантику запису (злиття полів, порядок спостережень, дедуплікацію) виконує ядро сервісу, однаково для всіх сховищ. Адаптер лише атомарно зберігає те, що вирішило ядро. Тому заміна сховища не змінює ні колектор, ні екстрактор, ні результат запису (ТЗ §12 п. 3).

## Ключові поняття

| Поняття | Значення |
|---|---|
| RAW-об'єкт | Збережений матеріал колектора: байти сторінки чи повідомлення разом із метаданими `Material` |
| Сутність | Структурований запис екстрактора (`EntityRecord`): тип, ключ, поля, спостереження |
| Канонічний ключ | Рядок `scope\|natural`, наприклад `shop-example\|{"sku":"A-100"}`; ідентифікує сутність у сховищі |
| Спостереження | `observation`: `observed_at`, `sequence`, `observation_id`; визначає, яке значення поля новіше |
| Історія | Кожне прийняте оновлення сутності, включно із запізнілим, з переліками `applied_fields` і `stale_fields` |
| `delivery_key` | Ключ технічної доставки; повтор того самого ключа повертає збережене підтвердження без нового запису |
| Пакет збереження | Маніфест `jane.storage-*` без коду: адаптер, що саме пише, формати й схема параметрів |
| Підключення | Опис місця в сховищі (`params`) і посилань на секрети (`secret_refs`); значення секретів у API не передаються |

Докладно семантика описана в [будові](internals.md).

- **Запис** іде через `handler.v1`: `StorageHandler` перевіряє пакет і параметри, читає вміст за `ContentRef`, а `StorageEngine` застосовує записи через адаптер.
- **Читання** (`storage.v1`) звертається до адаптера підключення напряму, без злиття.
- **Адаптери** знаходяться через entry point `jane.storage.adapters`: щоб додати сховище, досить установити пакет адаптера.
- **Registry** потрібен лише для пакетів збереження, яких немає серед вбудованих `jane.storage-*`.

## Сценарії

- **Етап збереження в завданні.** Orchestrator викликає `POST /v1/invocations` з `delivery_key` етапу; повтор після збою не створює дублів — [інтеграція](integration.md#композиція-в-jane).
- **Збереження без Orchestrator.** Сторонній застосунок реєструє підключення й надсилає матеріал або сутності сам — [швидкий старт](quickstart.md), [інтеграція](integration.md#самостійне-використання).
- **Актуальний стан і історія.** `GET /v1/entities` повертає поточні поля, `GET /v1/entity-history` — усі оновлення, зокрема запізнілі — [інтеграція](integration.md#читання-результатів).
- **Зміна сховища.** Інший пакет `jane.storage-*` і підключення іншого типу; колектор і екстрактор не змінюються — [адаптери](adapters.md).
- **Повторна обробка.** Orchestrator читає збережений RAW через `GET /v1/objects/{object_id}` і передає його етапам заново — [інтеграція](integration.md#повторна-обробка-збереженого-raw).
- **Новий тип сховища.** Пакет адаптера за протоколом `StorageAdapter` і набір сумісності C-01…C-16 — [новий адаптер](new-adapter.md).

## Автономність

Storage працює без Orchestrator, Registry та інших модулів Jane. Мінімальне середовище — Python 3.12, `uv` і каталог для файлового адаптера; перевірений запуск — у [швидкому старті](quickstart.md). Іншим адаптерам потрібне відповідне сховище — [залежності](dependencies.md).

Обмеження автономності:

- підключення, створені через `PUT /v1/connections/{id}`, зберігаються лише в пам'яті процесу; постійні описи задаються файлом `JANE_STORAGE_CONNECTIONS_FILE` — [конфігурація](configuration.md#підключення);
- пакет збереження, якого немає серед вбудованих, потрібно передати в запиті (`package_archive`) або налаштувати Registry.
