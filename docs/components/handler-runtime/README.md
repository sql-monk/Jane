# Handler Runtime

Handler Runtime виконує пакети обробників на Python — екстрактори й перетворення — в ізольованій контейнерній пісочниці та повертає результат через спільний API обробників `handler.v1`. Тип модуля — обробник; працює окремо, без Orchestrator і Registry.

Екстрактор і Handler Runtime — різні речі. **Екстрактор** — пакет обробника: код автора, маніфест `jane-package.json`, схеми й тести. **Handler Runtime** — сервіс, який перевіряє такий пакет і виконує його код у пісочниці. Код екстрактора пишуть за допомогою бібліотеки [jane-extractor-sdk](../extractor-sdk/README.md), встановленої в образ пісочниці.

## Призначення й межі

| Відповідає за | Не відповідає за |
|---|---|
| перевірку пакета: маніфест, дайджест, профіль виконання, залежності | зберігання пакетів і версій — це Registry |
| виконання коду пакета в пісочниці з лімітами часу, пам'яті, CPU, процесів і виводу | збереження сутностей — це етап обробника Storage |
| перевірку параметрів, вхідних даних і виходу за схемами пакета | отримання матеріалів із джерел — це колектори |
| класифікацію результату: `success`, `empty`, `unrecognized`, `failed` | розклади, ланцюжки етапів і повтори доставки — це Orchestrator |
| ідемпотентність за `delivery_key`, асинхронні job, тест-прогони | виклики LLM — це LLM gateway |

Сервіс не зберігає бізнес-результатів. Його власні дані — ключі ідемпотентності, job і результати викликів на час TTL, а також кеш розпакованих пакетів.

## Можливості

- **Виклик обробника** — `POST /v1/invocations` у режимі `sync` (200 з `HandlerResult` або 202, якщо не вклалося в `sync_response_max_ms`) чи `async` (одразу 202 з job).
- **Тест-прогін** — `POST /v1/test-runs` проганяє тести маніфесту й додаткові випадки без запису в робочі дані; результат — `TestReport` у job.
- **Джерела пакета** — архів у запиті (`package_archive`: inline, `file://` у дозволених каталогах, `download_url` з дозволених хостів) або Registry за `package_id` і `version`.
- **Пісочниця** — один свіжий контейнер Docker або Podman на виклик: без мережі, read-only, не root, без capabilities, з лімітами з конфігурації та запиту.
- **Профіль виконання** `python-extractor@1` — Python 3.12, SDK і фіксований набір бібліотек розбору HTML, XML і JSON.
- **CLI** `jane-handler-runtime` — `run` на локальному файлі, `test` для тестів пакета, `profile`, `build-image`, `serve`.
- **Стан** — у пам'яті (один екземпляр) або в PostgreSQL (кілька екземплярів зі спільними ключами й job).

## Автономність

Handler Runtime працює без інших модулів Jane. Обов'язкова лише контейнерна платформа з образом профілю: пакет можна передати архівом у запиті, а стан тримати в пам'яті. Registry потрібен, лише щоб брати пакети за ідентифікатором; PostgreSQL — лише для кількох екземплярів. Подробиці — [dependencies.md](dependencies.md).

## Обмеження

- **Мережа в пісочниці вимкнена.** Пакет із `access.network: allowlist` відхиляється з 422.
- **Керованих підключень немає.** Екстрактори не отримують облікових даних: `GET /v1/connections` повертає порожній список, `PUT` — 501 `not_implemented`.
- **Профіль один** — `python-extractor@1`; інші мови й профілі не підтримуються.
- **Бекенд `subprocess` не ізолює код.** Його дозволено лише для довірених локальних пакетів і тестів, у продакшні заборонено.
- **`s3://` без `download_url` не читається:** сервіс не тримає облікових даних сховищ.
- **Ізоляцію перевірено** на Docker Desktop 29.8 (Windows 11, Linux-контейнери) прогонами [quickstart.md](quickstart.md) і [operations.md](operations.md#перевірка-ізоляції); на Linux автоматичні тести ізоляції запускає CI (`just isolation`). Podman і `runsc` (gVisor) у цій документації не перевірялися.
