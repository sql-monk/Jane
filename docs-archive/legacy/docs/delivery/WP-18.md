## Відомі обмеження

- **oasdiff у CI — образ `tufin/oasdiff` без закріпленої версії** (як і раніше в `compat.py`, WP-00). Локально
  образ `latest` повідомляє `oasdiff version 322d7ae`. Тепер, коли oasdiff впливає на код виходу, зміна поведінки
  образу може зробити job червоним без змін у контрактах. Закріплення потребує перевіреного тегу (не перевіряв без
  мережі).
- **Job `contracts-compat` не запускався в GitHub Actions** (push заборонено): YAML розібрано, bash-фрагмент
  вибору бази відтворено локально, сама команда — локально на Windows з Docker.
- Для push у `main` порівняння з `github.event.before`; якщо цього коміту немає (force push) — merge-base з
  `origin/main`, тобто фактично з самим собою (0 змін).
- **`contracts-gen` — без моделей Pydantic.** datamodel-code-generator відмовляє на контрактах Jane і на їхньому
  Redocly-бандлі: `Modular references require an output directory, not a file` (`.jane/wp18-models-bundle.txt`).
  Це наявне обмеження `jane_kit.codegen.generate_models` (так само падає `just gen-client` на контракті; тести
  `test_wp00_contracts` генерують клієнт із `with_models=False`). Виправлення (вивід у теку-пакет або власний
  бандлер) — окрема задача, у WP-18 не робилось.
- `compat.py` змінено лише в коді виходу oasdiff; порівнювач і self-test не змінювались. Контракти (OpenAPI,
  схеми, Protocol-и) не змінювались, тому contract-guardian не викликався.

## Неперевірені інтеграції

- GitHub Actions (job `contracts-compat`, self-test у `contract`) — не перевірено на реальному CI.
- `oasdiff` як бінарник у PATH — не перевірено (лише Docker-образ і фальшивий `oasdiff.cmd` для коду виходу).
