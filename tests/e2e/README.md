# Наскрізні сценарії Jane

`tests/e2e/` — приймальні сценарії на справжніх сервісах у Docker. Кожен сценарій піднімає ізольований compose-стек, викликає сервіси лише через їхні HTTP API, перевіряє запити й відповіді за контрактами та прибирає стек після себе. Відповідність сценаріїв критеріям ТЗ §12 — [матриця приймання](../../docs/acceptance/README.md); опис сценаріїв — [сценарії](../../docs/acceptance/scenarios.md).

## Запуск

Потрібні uv, just і Docker із Compose v2. `just check` ці сценарії не запускає: каталог поза `testpaths` кореневого `pyproject.toml`.

```powershell
just e2e -v
```

Окремий файл або сценарій — аргументи pytest:

```powershell
just e2e tests/e2e/test_m1.py -v
just e2e -k s_m2_09 -v
```

`just e2e` виконує `uv run --all-packages pytest tests/e2e -m e2e …`. Без Docker сценарії пропускаються з причиною, а `just e2e` завершується успішно; щоб пропуск був помилкою, задайте `JANE_E2E_REQUIRED=1` (так працює job `e2e` у CI).

Повний прогін триває довго: перший запуск збирає образи всіх сервісів і образ пісочниці. У CI (`ubuntu-24.04`) весь workflow з job `e2e` займає близько 35–40 хвилин.

## Ізоляція й прибирання

- **Проєкт.** Основний стек сесії має compose-проєкт `JANE_E2E_PROJECT` або `jane-e2e-<6 символів хешу шляху checkout>`. Деякі модулі піднімають власні стеки з проєктом `<основний>-<назва>-<випадковий суфікс>` (ціни, Assistant, Registry, спільні ліміти хоста).
- **Порти** вибирає Docker на `127.0.0.1`; облікові дані генеруються для кожного стеку й зберігаються в `.jane/stack-<проєкт>.json`, тому `just env --project <проєкт>` працює і для стеку тестів.
- **Прибирання.** Після сесії фікстура `stack` (`conftest.py`) викликає `E2EStack.down(volumes=True)`: `docker compose down --remove-orphans -v --rmi local`, видалення контейнерів пісочниць із міткою `io.jane.e2e-project=<проєкт>`, образу пісочниці, файлу стеку й копії записів Telegram. Власні стеки модулів прибираються так само в `finally`. `JANE_E2E_KEEP=1` залишає стеки для діагностики — тоді приберіть їх самі командою `just down -v --project <проєкт>`.
- **Масштабування** в сценарії — фікстура `scale(service, n)`: після сценарію сервіс повертається до однієї репліки.

## Змінні середовища

| Змінна | Типово | Призначення |
|---|---|---|
| `JANE_E2E_PROJECT` | `jane-e2e-<хеш>` | compose-проєкт основного стеку |
| `JANE_E2E_KEEP` | не задано | `1` — не видаляти стеки після сесії |
| `JANE_E2E_REQUIRED` | не задано | `1` — пропущений сценарій або відсутність Docker є помилкою |
| `JANE_E2E_WAIT_TIMEOUT` | `900` | секунди очікування health-check |
| `JANE_E2E_DOCKER_SOCKET`, `JANE_E2E_DOCKER_GID` | визначаються автоматично | Docker API для пісочниць Handler Runtime |
| `JANE_E2E_SANDBOX_IMAGE` | `<проєкт>-python-extractor:1` | образ пісочниці |
| `JANE_E2E_LLM_MAX_REQUESTS_PER_MINUTE` | `120` | ліміт викликів LLM gateway у стеку тестів |

## Допоміжний код і дані

```text
tests/e2e/
├── conftest.py                # фікстури stack, require, scale, client, extractor, orchestrated; позначки
├── compose.e2e.yaml           # доповнення infra/compose.yaml для тестового стеку
├── compose.host-limits.yaml   # стек L2: інструментований testsite і дві репліки Web Collector
├── config/                    # seed LLM, пошук Assistant, виконавці Orchestrator, правила, підключення Storage
├── packages/                  # тестові пакети e2e.* (екстрактори, LLM-класифікація)
└── jane_e2e/                  # клієнти з перевіркою контрактів, керування стеком, кроки сценаріїв
```

- `jane_e2e/stack.py` — `E2EStack`: запуск сервісів, порти, `kill`/`pause`/`disconnect` контейнерів, масштабування, прибирання.
- `jane_e2e/clients.py` — HTTP-клієнт, що перевіряє запити й відповіді за `contracts/`.
- `jane_e2e/registry.py` — публікація пакетів у справжній Registry стеку.

## Замінники зовнішніх сервісів

- **LLM** — детермінований провайдер `fake` LLM gateway; відповіді задано в `config/llm-seed.yaml`. З реальним провайдером сценарії не виконуються.
- **Пошук вебджерел** для Assistant — статичний список `config/assistant-search.json`.
- **Telegram** — бекенд `recorded` Telegram Collector із записами `examples/telegram/recordings`.
- **Вебсайти** — детермінований тестовий сайт `tests/fixtures/testsite`; для R-04 — заглушка `package-host` з керованими завантаженнями.

`test_shared_host_replicas.py` посилається на `README.shared-hosts.md`, якого в каталозі немає.
