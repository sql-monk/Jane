# ADR-0005 — Bearer, scopes та спільний auth layer

Дата: 2026-10-11. Основа: `91876d1`. Стан: опис реалізованого рішення; новий текст у review.

## Проблема

Автономний сервіс має перевіряти власні API-виклики навіть при прямому доступі. Перевірка лише у проксі не захищає обхідний міжсервісний маршрут і ускладнює окреме використання.

## Розглянуті підходи

| Підхід | Наслідок |
|---|---|
| Лише gateway auth | Простий єдиний вхід; прямі API лишаються незахищеними |
| Власна auth-реалізація кожного сервісу | Можливі різні правила та виправлення |
| Спільний layer, перевірка в кожному сервісі | Узгоджена семантика й автономні межі |

## Рішення

Jane Kit надає режими `none`, `api_key` і `jwt`. Bearer-токен визначає principal і scopes. OpenAPI декларує `x-jane-scope`; таблиці операцій у сервісі зіставляються з контрактами. Відсутня або неповна auth-конфігурація завершує старт помилкою.

## Наслідки

`none` використовується локально; remote запуск потребує явного винятку для ізольованих тестів. API key перевіряється за digest або secret_ref. JWT використовує асиметричні алгоритми, issuer, audience й expiry. Admin може отримувати токен через OIDC/PKCE; сервіс перевіряє його незалежно від UI.
