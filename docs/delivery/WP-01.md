## Відомі обмеження

  `jane-codegen models` з бандла (`redocly bundle`), як радить скіл `jane-contracts`.

  S3 API — обґрунтування в [infra/README.md](../../infra/README.md).

- Git pre-commit хук не встановлено автоматично (див. вище); без gitleaks хуки лише попереджають.
- `.gitattributes` задає LF у робочих копіях; щоб наявні checkout із CRLF (через `core.autocrlf=true`) перейшли на

### Знахідки

1. **llm: тайм-аут провайдера з профілю.** llm оголошує `provider.connect_timeout_ms`,
   `provider.request_timeout_ms` і `provider.retries` як контрактні `timeouts.*` / `retries` (`ClientLimits`), тож
   профіль, розрахований на HTTP-завантаження (`timeouts.request_timeout_ms` = 30 000), замінює типові 120 с
   виклику моделі. Для довгих відповідей реального провайдера 30 с може бути мало. Реальний провайдер
   **не перевірено на реальному сервісі**; механізм лише виконує декларацію сервісу. Так само `clients.*`
   асистента й `retries` ядра storage отримують загальні `timeouts` / `retries` профілю. Рішення — за власниками
   (запити нижче).
2. Колектори через власний `translate_layer` для шару платформи **мовчки ігнорують і опечатки** (лише
   `log.debug`), а jane-kit тепер їх відхиляє — поведінка різна (див. «Подальша уніфікація»).
3. Сервіси, що рахують ліміти на кожен запит (storage, handler-runtime, llm, assistant), щоразу перечитують файл
   платформи (так було й до змін); зіставлення шляхів контракту кешується на модель (`functools.cache`).

  `shared` на нього не впливає, змін не потрібно.
