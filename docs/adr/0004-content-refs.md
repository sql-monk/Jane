# ADR-0004 — ContentRef та окреме збереження RAW

Дата: 2026-10-11. Основа: `91876d1`. Стан: опис реалізованого рішення; новий текст у review.

## Проблема

ТЗ §4 вимагає передавати великі матеріали посиланням або потоком, а §5 визначає збереження RAW окремою операцією. Транспорт матеріалу не повинен вимагати від колектора запису бізнес-даних у цільову базу.

## Розглянуті підходи

| Підхід | Наслідок |
|---|---|
| Увесь вміст у JSON | Просто для малих матеріалів, великий трафік і пам’ять |
| Посилання без перевірки | Менший документ, але ризик підміни й недоступності |
| Inline або перевірений blob | Контроль розміру, хешу, доступу й строку життя |

## Рішення

ContentRef має форму inline або blob. Виробник обирає спосіб за transfer limits; читач перевіряє політику адрес, розмір та SHA-256. Поточний транзитний backend створює файли зі строком життя. Постійне збереження виконує Storage через адаптер.

## Наслідки

Для file URI споживачам потрібен явно дозволений корінь і доступ до того самого вмісту. Для download URL потрібен allowlist. Reader не отримує секрети адаптера та не читає довільний `s3://`. Повторна обробка має читати збережений RAW через Storage.
