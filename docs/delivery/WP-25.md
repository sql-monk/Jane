# WP-25. Матеріали та стан сховищ

**Гілка:** `wp/25-materials-storage-browser` · **База:** `9936d65` · **Стан:** review

## Результат

- Матеріали автоматично відкриваються для налаштованих сховищ через storage `/v1/connections`, без ручного введення connection_id. Кожне сховище має незалежну курсорну пагінацію, оновлення та помилки; відмова одного не приховує інші.
- Вибір сховища, джерело й дати збереження передаються в API. Межа `until` не включається. Некоректні дати та обернений/порожній період явно блокують запити. Фільтр медіатипу чесно позначено як локальний для завантажених матеріалів.
- Картка відкривається за deep link з object_id і connection_id, показує вміст без HTML-виконання, читабельний JSON, метадані, посилання на джерело та історію обробки. Повторна обробка RAW зберігає identity сховища й режими material/object/observation наявної форми. Для документів результатів є перехід до результатів.
- Новий розділ «Сховища»: cached snapshot доступності, час останньої перевірки, діагностика, кількість/байти лише за API. `null` показано як «Невідомо», невиконану перевірку — «Не перевірено». Явна перевірка має Idempotency-Key та оновлює snapshot. Секрети/параметри підключень не показуються.
- Окремий CSS і адаптивні матеріали/сховища: при 390px навігація прокручується горизонтально, таблиця прокручується всередині, довгі метадані переносяться. Wide та narrow screenshots переглянуто через view_image.

Нових лімітів не зашито. Перевірка snapshot виконується лише явно користувачем; автоматичного сканування сховища при відкритті сторінки немає.

## Відомі обмеження й неперевірені інтеграції

- Медіатип фільтрується лише в завантажених сторінках: контракт WP-24 не має серверного фільтра типу. Статус обробки доступний у простежуваності, N+1 trace-запити для рядків не виконуються.
- Discover connections також курсорний, наступні сховища відкриваються кнопкою «Показати ще». Показані списки не стверджують глобальне сортування/повний total.
- Зовнішні PostgreSQL/S3/MinIO та інші реальні адаптери: не перевірено на реальному сервісі у WP-25. Coordinator WP-27 виконує окремий filesystem API smoke.
- Typecheck/browser build перевірено з temporary `generated/storage.ts` WP-24. Координатор погодив копію без staging; файл не входить у коміт WP-25. При інтеграції WP-24 мусить передувати WP-25.

## Виправлення після рев'ю R1

- Статистика більше не запускається через синхронний connection test. «Перевірити зараз» викликає контрактний `POST /v1/storage-status/checks` з `{connection_id}` і Idempotency-Key, отримує 202 Job, а `useJob` опитує storage `/v1/jobs/{job_id}` з наявним конфігурованим backoff.
- Показуються черга, виконання, прогрес, завершення та помилка. Кнопку повторної перевірки заблоковано до terminal стану. При помилці читання Job доступне «Оновити перевірку». Snapshot оновлюється після terminal outcome; queued/running не викликають передчасного перезавантаження snapshot.
- Вміст матеріалу відображається як точний вихідний текст без JSON.parse/stringify: великі числа, exponent lexemes, пробіли та дублікати ключів не змінюються. Регресія перевіряє реальний content-preview з `9007199254740993` та `1e400`, поряд із інертним HTML deep link.
- Причини недоступності статистики (`not_checked`, `adapter_statistics_not_supported`, `statistics_check_failed`, `check_failed`) переведено у короткі українські повідомлення. Невідомі reason codes мають чесне нейтральне повідомлення, без виведення внутрішнього коду в інтерфейс.
- Unit: pending check не створює duplicate POST, передає потрібне connection_id, не оновлює cached snapshot до завершення, після завершення оновлює стан і розблоковує кнопку. Окремо перевірено failed terminal Job та показ помилки. Browser routes оновлено на 202 Job + polling, assertions discovery/pagination/inert HTML збережено.
