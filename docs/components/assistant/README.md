# Assistant

Assistant — сервіс `services/assistant`, який за допомогою LLM готує нові джерела й вдосконалює екстрактори. За назвою чи посиланням він знаходить джерело, збирає різноманітну вибірку матеріалів, визначає типи матеріалів, сутності й поля, пропонує кілька варіантів правил збору з охопленням, вартістю й ризиками, знаходить, адаптує або створює пакети екстракторів і перевіряє їх тестами. Тип модуля — координація: сам нічого не збирає й не виконує, а викликає API сусідніх модулів (`assistant.v1`).

## Призначення й межі

| Відповідає за | Не відповідає за |
|---|---|
| сесію підключення джерела: пошук, вибірка, аналіз, варіанти, прийняття | збір матеріалів — це колектор |
| пошук, адаптацію форку або створення пакета екстрактора, тести на зразках | виконання коду екстрактора — це Handler Runtime |
| вдосконалення екстрактора на проблемних прикладах: нова версія або форк | зберігання пакетів, версій і статусів — це Registry |
| перевірку відповідей моделі: правила в межах джерела, безпечний код, схеми | виклик моделі, бюджети рівнів і облік — це LLM gateway |
| класифікацію невідомого матеріалу за увімкненим прапорцем | виконання завдань і активацію версій на прив'язках — це Orchestrator |

Створені пакети й правила належать Registry, джерела й завдання — Orchestrator. Власні дані Assistant — сесії підключення, job і ключі ідемпотентності ([internals.md](internals.md#власні-дані)).

## Можливості

- **Підключення джерела** — `POST /v1/onboarding-sessions`: URL, `@канал` або назва; адаптивна вибірка до впевненості `min_onboarding_confidence` у межах бюджету; варіанти правил збору; для кожного типу сутності — `bind_existing`, `fork` або `create`.
- **Вибір кандидата** — `POST …/candidate-selection`, якщо пошук за назвою дав кілька схожих джерел.
- **Прийняття варіанта** — `POST …/proposals/{proposal_id}/acceptance`: публікація правил і пакетів у Registry як чернеток, запис результатів тестів, чернетки джерела й завдання; з `activate: true` — погодження версій і створення джерела й завдання в Orchestrator.
- **Вдосконалення екстрактора** — `POST /v1/improvement-runs`: виправлена версія проходить старі тести, нові тести з проблемних прикладів, регресії на успішних і тести кожної прив'язки; інакше — форк або «невирішено».
- **Невідомий матеріал** — `POST /v1/unknown-materials`: класифікація й порада (`new_extractor`, `extend_rules`, `expand_entity_types`, `none`), лише якщо `forward_unknown_to_llm: true`.
- **Списки** — `GET /v1/onboarding-sessions`, `GET /v1/improvement-runs` з курсорною пагінацією й фільтрами.
- **Вміст джерел — дані, не інструкції**: матеріали потрапляють лише в дані запиту до моделі; її відповіді перевіряються до застосування.

## Автономність

Assistant запускається окремо, але працює лише разом із сусідами: кожна операція вимагає своїх. Без потрібного сусіда операція завершується `upstream_unavailable` з поясненням, якого сусіда не налаштовано.

| Операція | Обов'язкові сусіди | Опційні |
|---|---|---|
| Підключення джерела | LLM gateway, колектор потрібного типу, Handler Runtime; Registry — для прийняття | Registry для пошуку готових екстракторів, Orchestrator для активації, пошуковий провайдер для назв |
| Вдосконалення | LLM gateway, Registry, Handler Runtime | Orchestrator (прив'язки, групи проблем, активація), Storage (`material_ref`) |
| Невідомий матеріал | LLM gateway | Orchestrator (очікувані типи сутностей джерела) |

Orchestrator для роботи Assistant не обов'язковий: без нього прийняття повертає чернетки джерела й завдання замість їх створення. Подробиці — [dependencies.md](dependencies.md).

## Обмеження

- **Якість залежить від моделі.** З провайдером `fake` LLM gateway Assistant проходить увесь процес, але класифікація не розрізняє типів, тому реальне підключення дає `insufficient_sample` (перевірено в [quickstart.md](quickstart.md)). Повний цикл підключення з реальною моделлю в цій документації не перевірено.
- **Пошук за назвою** вимагає налаштованого провайдера (`static` або `http_json`); без нього приймаються лише URL і `@канал`.
- **Dev-стек** (`infra/compose.yaml`) підключає Assistant лише до LLM gateway, Handler Runtime і Storage. Registry, колектори й Orchestrator додає `infra/compose.local.yaml` за зразком `infra/compose.local.example.yaml`.
- **Мови екстракторів** — лише Python-пакети для Handler Runtime; згенерований код може імпортувати тільки модулі зі списку `generated_code_allowed_modules`.
- **Великі HTML-сторінки** скорочуються до `material.max_fixture_bytes`: модель бачить і екстрактори тестуються на скороченій копії; варіант називає цей ризик.
