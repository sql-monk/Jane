# ADR-0001 — Автономні модулі й контрактна композиція

Дата: 2026-10-11. Основа: `91876d1`. Стан: опис реалізованого рішення; новий текст у review.

## Проблема

ТЗ §4 вимагає прямого використання колектора й екстрактора стороннім застосунком. Обов’язкова залежність кожного виконавця від Orchestrator або його таблиць порушила б цю властивість.

## Розглянуті підходи

| Підхід | Наслідок |
|---|---|
| Спільна бізнес-база й центральні виклики | Менше API, але зв’язані схеми та життєві цикли |
| Автономні сервіси з контрактами | Окремі залежності, заміна реалізацій і версіоновані межі |

## Рішення

Кожен сервіс приймає контрактні документи через `/v1` та зберігає власний стан. Orchestrator маршрутизує етапи через налаштованих виконавців; Registry надає пакети. Runtime також приймає локальний артефакт.

## Наслідки

Сторонній клієнт може вибрати потрібні модулі. Підтримка сумісності охоплює формат, помилки, ідемпотентність, scopes та поведінку; службові сховища залишаються відповідальністю власників.
