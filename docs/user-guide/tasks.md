# Завдання й розклад

Завдання описує, що зібрати з джерела, якими етапами обробити й коли запускати. Етапи утворюють ланцюжок: етап збору (`collect`) і етапи-обробники (`handler`) з точною версією пакета. Ланцюжок може розгалужуватися: один і той самий вихід можна передати кільком етапам.

## Список завдань

Сторінка «Завдання» (`/tasks`) показує ідентифікатор, назву, джерело, розклад, наступний запуск, стан останнього запуску й «Увімкнено». Фільтри: «Пошук у завантажених завданнях», «Активність» («Усі завдання», «Увімкнені», «Призупинені»), «Джерело». У рядку — «Запустити» ([запуск і спостереження](runs.md)) і «Історія» (запуски завдання).

## Нове завдання

Передумови: створено джерело ([підключення джерела](sources.md)); пакети, які стануть етапами, мають погоджені версії ([пакети й версії](packages.md)).

1. Натисніть «Нове завдання». Відкривається вкладка «Конфігурація».
2. Заповніть:

   | Поле | Значення |
   |---|---|
   | Ідентифікатор (task_id) | після створення не змінюється |
   | Назва | людська назва |
   | Джерело (source_id) | ідентифікатор джерела |
   | Передавати в LLM невідомі сторінки | «як у джерела», «увімкнено» або «вимкнено» |
   | Завдання увімкнено | вимкнене завдання не запускається за розкладом |
   | Явний перелік URL | по одному в рядку; замість правил джерела |

3. Налаштуйте «Розклад» ([Розклад](#розклад)).
4. За потреби заповніть JSON-редактори «Ліміти рівня завдання» ([ліміти](limits.md)) і «Повторні спроби».
5. Перейдіть на вкладку «Ланцюжок» і опишіть етапи ([Ланцюжок етапів](#ланцюжок-етапів)).
6. Натисніть «Перевірити в оркестраторі», потім «Створити завдання».

Очікуваний результат: адмінка переходить на сторінку «Завдання <task_id>» і показує «Збережено. Поточні запуски продовжуються зі старою конфігурацією.»

## Ланцюжок етапів

Вкладка «Ланцюжок» має два розділи:

- «Ланцюжок обробки (етапи й переходи)» — граф етапів. Стрілки йдуть від `inputs[].from` до етапу; підпис стрілки — що передається (`select`), якщо це не звичайний вихід, або позначка умови.
- «Етапи (TaskConfig.stages)» — JSON-редактор масиву етапів.

Нове завдання починається з одного етапу збору:

```json
[
  {
    "stage_id": "collect",
    "kind": "collect",
    "collector": { "collector": "web", "mode": "full" }
  }
]
```

Кнопка «Додати етап-обробник» додає в кінець етап `stage-<n>` з порожнім пакетом і входом від останнього етапу:

```json
{
  "stage_id": "stage-2",
  "kind": "handler",
  "handler": { "package_id": "", "version": "" },
  "inputs": [{ "from": "collect" }]
}
```

Заповніть `handler.package_id` і `handler.version` погодженою версією пакета. Правила, які нагадує підказка над редактором:

- розгалуження — кілька етапів з тим самим `inputs[].from`, наприклад збереження RAW і екстрактор від одного етапу збору;
- умова переходу — поле `when`;
- що саме передати — `select`: `output`, `input_material`, `problems`, `unmatched_materials`.

Повна схема етапу — [task-config.schema.json](../../contracts/schemas/task-config.schema.json); приклади ланцюжків — у документації [Orchestrator](../components/orchestrator/README.md).

## Розклад

Розділ «Розклад» на вкладці «Конфігурація»:

| Тип розкладу | Поле | Приклад |
|---|---|---|
| вручну | — | лише ручні запуски |
| одноразово | Час запуску (RFC 3339) | `2026-10-01T02:00:00Z` |
| cron | Cron (5 полів) | `0 2 * * 0` |
| інтервал | Інтервал, секунд | `3600` |

Для всіх типів, крім «вручну», також:

- «Часовий пояс» — типово `UTC`;
- «Якщо попередній запуск ще йде» — «пропустити», «поставити в чергу» або «дозволити паралельно»;
- «Розклад увімкнено» — вимкнений розклад зберігається, але не запускає завдання.

Колонка «Наступний запуск» у списку завдань показує час, обчислений Orchestrator.

## Перевірка й збереження

- Під формою може з'явитися список «Помилки конфігурації» — помилки JSON або відповідності схемі. Поки він є, «Створити завдання» / «Зберегти» неактивні.
- «Перевірити в оркестраторі» надсилає чернетку на перевірку без збереження. Результат — «Конфігурація: ok» або «failed», для кожної помилки й попередження — рядок «Помилка» чи «Попередження», а також ефективне значення «Передавати в LLM невідомі сторінки».
- «Зберегти» для наявного завдання застосовує зміни до нових запусків. Якщо завдання змінив хтось інший, з'явиться помилка `precondition_failed` — перезавантажте сторінку.
- «Видалити» (з необов'язковою причиною) видаляє завдання й повертає до списку.
