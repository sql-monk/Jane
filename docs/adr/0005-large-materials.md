# ADR-0005. Великі матеріали за посиланням (ContentRef)

- **Статус:** прийнято, діє частково — транзит через S3 не реалізовано.
- **Звірено з кодом:** ревізія `48389a3`, 2026-10-11.

## Контекст і проблема

Сторінки, медіа Telegram і збережені RAW можуть мати мегабайти. ТЗ вимагає для великих матеріалів потокової передачі або передачі посилання (ТЗ §4). Вміст передається між колектором, Orchestrator, обробниками й Storage, які можуть працювати як окремі процеси без спільної файлової системи.

## Варіанти

1. **Єдиний тип `ContentRef`: вміст inline до порогу, більший — посиланням на blob із розміром і SHA-256.**
2. Завжди inline — прості API, але тіла запитів необмеженого розміру й пам'ять кожного сервісу.
3. Потокова передача (chunked, gRPC streams) — складні повтори й ідемпотентність, кожен виклик тримає з'єднання на весь час передачі.
4. Спільна файлова система для всіх сервісів — прив'язує розгортання до одного вузла.

## Рішення

Обрано варіант 1. Схема — [content-ref.schema.json](../../contracts/schemas/common/content-ref.schema.json); читання й запис — `libs/jane-kit/src/jane_kit/content.py`.

- **`inline`** — `media_type`, `encoding` (`utf-8` або `base64`), `data`, опційно `size_bytes`, `sha256`. Використовується до `transfer.inline_max_bytes` (типово 262144 байти в колекторах і Assistant, 1 MiB у Storage).
- **`blob`** — `uri` (`s3://…` або `file:///…`), `media_type`, `size_bytes`, `sha256`; опційно `download_url`, `store` (`transit` або `persistent`), `expires_at`.
- **Транзитне сховище** — `FileTransitStore`: `<transit_dir>/<сервіс-виробник>/YYYY/MM/DD/…`, очищення за `transfer.transit_ttl_seconds` (типово 7 днів). Без `transit_dir` сервіс передає лише inline, а більший матеріал відхиляє з `limit_exceeded`.
- **Постійні об'єкти** (RAW) пише лише Storage.
- **Читання недовірене.** `file://` дозволено лише з каталогів `BLOB_ROOTS` сервісу, `download_url` — лише до хостів із `DOWNLOAD_HOST_ALLOWLIST`, без редиректів; обидва типово вимкнено. `s3://` без `download_url` відхиляється. Після читання перевіряються розмір і SHA-256.
- **Межа тіла запиту** — `transfer.max_request_body_bytes`; модель помилок передбачає `413 payload_too_large` з порадою передати вміст як blob ([errors.md](../../contracts/docs/errors.md)). Явну перевірку розміру тіла в коді знайдено лише в Registry.

## Наслідки

- API лишаються JSON; великий вміст не проходить через пам'ять Orchestrator.
- Цілісність перевіряється дайджестом незалежно від способу передачі.
- **Обмеження:** транзит через S3/MinIO (бакет `jane-transit`) і генерацію presigned `download_url` не реалізовано — у `content.py` це зазначено явно. `file://` працює лише на одному вузлі зі спільним томом; у dev-стеку це том `storage-data`, змонтований у Storage на запис і в Handler Runtime та LLM gateway лише для читання ([масштабування](../operations/scaling.md#обмеження)).
- Повторна обробка збережених RAW використовує постійні `file://`-посилання Storage або його транзитні blob для RAW без постійного URI (`JANE_STORAGE_CONTENT_FILES_DIR`, `JANE_STORAGE_TRANSIT_DIR`).
