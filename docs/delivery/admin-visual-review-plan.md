# Виправлення візуального рев'ю адмінки

Користувач погодив усі зауваження рев'ю, паралельне виконання, повний CI, перевірку й розгортання в `jane-demo` та перенесення прийнятої ревізії в GitHub `main`. База: `0b554fce30bce5aa7def84d351575e23862f66b8`. Координатор працює в `codex/admin-materials-chains`; інші активні checkout та їхні зміни не входять до цього пакета.

## Пакети й власність

Точні шляхи нових WP — у [карті власності](../../.codex/wp-paths.json). Сумісний [хук](../../.codex/hooks/jane_wp.py) підтримує також попередню карту `.claude`. У Windows шлях `.Codex` з інструкцій користувача відповідає цьому самому каталогу; у Linux використовується написання `.codex` із Git.

|---|---|---|
| 28 | Каталог типів результатів, пошук у всьому сховищі, контекст джерела й статистика PostgreSQL | Дані можна знайти без знання кодів типів і попереднього завантаження сторінок; статистика розрізняє RAW та сутності; API сумісний із main |

## Правила виконання

- По одному ізольованому checkout на виконавця; три виконавці паралельно, координатор веде WP-31/32.
- Worker не змінює чужі файли, не зливає та не публікує main. Запити до спільних типів/компонентів передає координатору.
- API розширюються лише сумісно. Оновлюються приклади, адаптери та згенеровані клієнти. Guardian незалежно переглядає усю дельту контрактів.
- Спочатку адресні перевірки кожного WP й незалежний wp-reviewer, потім один повний workflow_dispatch на інтегрованій ревізії. Падіння усуваються й CI повторюється для виправленого SHA.
- Кількості, зв'язок із запуском та діагностику не вигадувати; якщо даних немає, UI явно показує недоступність. Не читати чужі таблиці.
- Робочі дані, секрети, порти й томи зберігаються. Перед оновленням сервісів — резервування й можливість повернення. Паралельні роботи з документацією й каталогами не включаються в наш commit.

## Матриця зауважень

WP-28: порожній початковий перегляд результатів, пошук лише у вибірці, статистика сутностей. WP-29: втрата чернеток, передчасна англомовна валідація, дублювання технічних властивостей, списки значень, вибір джерел, успадковані правила, довгі форми. WP-30: підсумок і причина збою, контекст результатів, масова повторна обробка одного RAW, unknown тестів, відкат без історії, порожні успішні елементи, великі JSON трасування, показники проблем і діагностика підключень, деталізація змін аудиту. WP-31: інші підключення й налаштування, мобільне подання, час і тривалість, локалізація, loading/empty/error, посилання й фільтри аудиту. Кінцевий звіт містить статус кожного пункту та межі перевірки.
