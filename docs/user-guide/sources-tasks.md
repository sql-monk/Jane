# Джерела та завдання

Джерело описує сайт або Telegram-канал; завдання визначає, що й коли з нього отримувати, які пакети застосувати та куди записати вихід.

## Відкрити приклад

Передумова — [demo](../getting-started/README.md). У **Джерела** знайди `testsite-shop`, відкрий його параметри й посилання на завдання. У **Завдання** вибери `testsite-catalog`.

Редактор завдання містить етапи, зв’язки, пакети, підключення й розклад. Зіставлення `connections` задається на етапі; підключення створюються в розділі **Підключення** й містять посилання на секрети.

## Створити власне завдання

1. У **Джерела** створи джерело з типом `web` або `telegram` і його адресою.
2. У **Завдання** задай ідентифікатор, джерело та етапи. Для Web мінімальний шлях — збір, екстрактор, збереження.
3. Вибери наявні пакети й версії, зістав потрібні підключення.
4. Виконай валідацію. Переглянь помилки сумісності входів, версій, підключень і DAG; виправ їх перед збереженням.
5. Запусти тестовий режим, перевір вихід, потім звичайний запуск.

Тестовий режим перевіряє обробку; конкретний ефект збереження визначає обробник і переданий `test_mode`. Передумови стороннього сервісу наведені у [модульному каталозі](../components/README.md).

## Як оцінити результат

Завдання має зберегтися та відкритися повторно з тими самими етапами. Валідація має повертати `valid: true`; успішний запуск — дати очікувані сутності. Для перевірки прикладу використовуй [verify](../getting-started/README.md#результат).

За конфлікту редагування (`412`) перечитай актуальну версію й перенеси зміни. Не перезаписуй чужі правки старим ETag.
