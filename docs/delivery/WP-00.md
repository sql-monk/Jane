## Результат

Зроблено все зі змісту WP-00 (plan.md §5):

- **ADR** — [`docs/adr/`](../adr/README.md), формат «контекст → рішення → наслідки → альтернативи»:
  - [0001](../adr/0001-baseline-stack.md) — plan.md §2 **підтверджено без заміни**, з уточненнями (генерація моделей/клієнтів, pull-потік колектора, моки);
  - [0002](../adr/0002-package-registry.md) — репозиторій пакетів (ТЗ §13.2): **власний сервіс registry + незмінні content-addressed zip-архіви (sha256) у blob-сховищі**, метадані у власній БД; OCI/Git/PyPI оцінено й відхилено;
  - [0003](../adr/0003-python-sandbox.md) — пісочниця: **контейнер на виклик через Docker/Podman API** (`--network none`, read-only, ліміти з `limits.sandbox`, kill за wall-time), gVisor опційно, `subprocess` лише для dev-тестів;

  - [0005](../adr/0005-authentication.md) — `Bearer` у всіх API; режими `none|api_key|jwt`, scopes; адмінка — OIDC + PKCE через reverse proxy;
  - [0006](../adr/0006-secrets-and-connections.md) — `Connection` з `secret_refs` (`env:`/`file:`/`vault:`), значення розв'язує лише виконавець; реєстр в оркестраторі синхронізує визначення;
  - [0007](../adr/0007-target-environments.md) — модель лімітів і профілі `dev-laptop`, `ci`, `single-node` (типове рішення, див. «Питання до людини»);

## Конфігурація й ліміти

WP-00 не має сервісу; числових лімітів у контрактах не зашито. Модель — `contracts/schemas/common/limits.schema.json`
(рівні platform → source → task → stage, `hard_caps`, `EffectiveLimits` з походженням). Довідкові стартові
профілі (не виміряні; перевіряє WP-14):

| Параметр | Типове значення (dev-laptop) | Де задається |
|---|---|---|
| `transfer.inline_max_bytes` | 262144 | `contracts/examples/schemas/common/limits@PlatformLimits/dev-laptop.json` |
| `transfer.transit_ttl_seconds` | 604800 (7 діб) | те саме |
| `transfer.idempotency_ttl_seconds` | 86400 | те саме |
| `timeouts.sync_response_max_ms` | 25000 | те саме |
| `sandbox.memory_mb` / `cpu_cores` / `wall_time_ms` | 512 / 1 / 30000 | те саме |
| `rate.requests_per_second_per_host` | 1 | те саме |
| `queue.max_unacked_materials` | 500 | те саме |
| `llm.budget` | 5 USD/день | те саме |

Інструменти: Redocly `@redocly/cli@2.54.3`, Prism `@stoplight/prism-cli@5.16.0` (закріплені в командах).

## Відомі обмеження

- `mock.py` не валідує тіла запитів за схемою (лише обов'язкові заголовки, наявність і синтаксис JSON) — для валідації є Prism.
- `compat.py` — евристичний порівнювач схем (не повна логіка JSON Schema): зміни `oneOf/anyOf` з різною кількістю варіантів і зміни семантики без зміни схеми позначаються WARNING або потребують ручної перевірки (це закладено в `contract-guardian`). Образ `tufin/oasdiff` не закріплено за версією.
- Redocly під час бандлингу неправильно обробляє `$ref: "#"` і `$ref` усередині `if/then` зі `properties`; схеми написано без цих конструкцій (відповідність `kind ↔ entry` маніфесту — `oneOf` + перевірка registry).
- Приклади `contracts/examples/openapi/*.json` — обгортки прикладів зі `examples/schemas/`; їх згенеровано одноразово, при зміні одного треба оновити інший (обидва перевіряються лінтером на валідність).
- SDK екстракторів у скілі `jane-handler-package` — чернетка (фіналізує WP-06).

## Неперевірені інтеграції

- Контракти не перевірені реальними реалізаціями (їх ще немає) — лише мок-сервери (mock.py, Prism) і лінтер.
- Пісочниця (ADR-0003), OIDC (ADR-0005), Vault-провайдер секретів (ADR-0006) — рішення без прототипу; перевірка — WP-06, WP-12/WP-01, опційно.
- Профілі лімітів — не виміряні на цільових середовищах (WP-14).

## Питання до людини

1. **Цільові середовища (критерій 13).** Прийнято типово: `dev-laptop` (Docker Desktop Windows/Linux, 4 vCPU/8–16 ГБ), `ci` (GitHub Actions ubuntu, 4 vCPU/16 ГБ), `single-node` (Linux VM 8 vCPU/32 ГБ, Compose). Чи це ваші середовища? Чи потрібен Kubernetes у v1?
2. **CI-платформа:** GitHub Actions чи GitLab CI (впливає на профіль `ci` і роботу WP-01)?
3. **IdP для адмінки:** є корпоративний OIDC (Entra ID, Keycloak, Google)? Якщо ні — чи прийнятний dev-режим `api_key` для першого робочого розгортання?
4. **Секрети:** достатньо посилань `env:`/`file:` (секрет кладе оператор у середовище), чи потрібне вбудоване шифроване сховище секретів із введенням через адмінку?
5. **Пісочниця в прод:** чи дозволено handler-runtime доступ до Docker API (через socket-proxy), чи потрібен rootless Podman / gVisor / окремий вузол?
6. **LLM-провайдери й валюта бюджетів:** які провайдери підключати першими, бюджети в USD — ок?
7. **Політика robots для власних ресурсів:** хто має право вмикати `owner_policy` (роль у адмінці)?
