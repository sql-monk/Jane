## Частина C — ТЗ §4, безпека, відкриті питання

Архітектурних порушень ТЗ §4 немає (чужі таблиці не читаються, автономні компоненти не залежать від оркестратора,
ліміти з конфігурації). `gitleaks git`: 482 коміти, 0 витоків. Пісочниця runtime обмежена правильно.

Блокери безпеки (підтверджено координатором у коді):
- **B1.** llm (`jane_llm/packages.py` `read_content`) і assistant (`jane_assistant/content.py` `material_bytes`)
  читають будь-який `file://` (напр. `/proc/self/environ`) і завантажують `download_url` без allowlist.
- **B2.** ADR-0005 вимагає перевірки токена й scopes у кожному сервісі; фактично лише orchestrator і registry;
  `AUTH_MODE` у решти 6 сервісів лише показується в `/v1/info`; JWT не перевіряє жоден сервіс.

Варто: SSRF через `download_url` у handler-runtime; політика вихідних адрес Web Collector (link-local/metadata);
дайджест SDK (`ZIP_DEFLATED`) ≠ канонічного архіву registry; `keepalive_expiry` клієнта оркестратора; TOCTOU
`file:`-секретів у telegram і llm; 500 замість 422 на невалідний порт у llm. Тріаж відкритих запитів: блокери —
B1, B2; решта (пакет уточнень контрактів через contract-guardian, рефакторинг jane-kit, `provider.*`, бюджет 0
асистента, спільний ліміт хоста між екземплярами) — після M3.
