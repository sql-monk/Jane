# Запуск і спостереження

Як запустити завдання вручну, стежити за прогресом етапів, знайти помилки елементів і колектора, зупинити запуск і повторно обробити збережені матеріали.

## Швидкий запуск

Передумова: завдання збережене ([завдання й розклад](tasks.md)).

1. На сторінці «Завдання» або в блоці «Завдання під рукою» на «Огляді» натисніть «Запустити» біля завдання.
2. У вікні «Запуск <task_id>» оберіть «Режим запуску»:
   - «Тестовий — без запису в робочі дані» (вибрано за замовчуванням);
   - «Робочий — зі збереженням результатів» — з'явиться попередження «Етапи збереження запишуть результати в робочі сховища.»
3. За бажання вкажіть «Причина запуску».
4. Натисніть «Підтвердити запуск».

Очікуваний результат: адмінка відкриває сторінку нового запуску (`/runs/<run_id>`) зі станом `queued` або `running`.

## Запуск зі сторінки завдання

Вкладка «Запуски» сторінки завдання дає більше параметрів:

1. «Причина» — для журналу.
2. «URL для цього запуску (необов'язково)» — адреси через пробіл; замінюють вхід завдання лише для цього запуску.
3. «Тестовий режим (без запису в робочі дані)» — за замовчуванням вимкнено.
4. Натисніть «Запустити».

Очікуваний результат: відкривається сторінка запуску. Нижче на вкладці — «Історія запусків» завдання: стан, тригер, позначка тестового режиму, час створення.

## Список запусків

Сторінка «Запуски» (`/runs`) показує запуск, завдання, стан, тригер, «Тест», «Створено», «Завершено». Фільтри: «Завдання» і «Стан» (`queued`, `running`, `cancelling`, `succeeded`, `failed`, `cancelled`). Поки в списку є незавершені запуски, він оновлюється сам; «Оновити список» перечитує одразу. У колонці «Дії» — «Деталі» і, для незавершених, «Зупинити».

## Сторінка запуску

Верхній блок: завдання, стан, тригер, «Тестовий режим», час створення, початку й завершення, «Витрати LLM», «Backpressure» («так, збір пригальмовано», якщо обробка не встигає за збором), «Версія конфігурації» завдання, з якою виконується запуск. Помилка запуску показується блоком «Помилка запуску». Сторінка оновлюється сама до завершення запуску.

| Вкладка | Що показує |
|---|---|
| Прогрес етапів | для кожного етапу — пакет і лічильники елементів за станами; нижче — загальні лічильники запуску |
| Елементи й помилки | елементи етапів: матеріал (посилання на простежування), стан, результат, спроби, «Доступний з», «Історія спроб», пакет, код помилки. Фільтри «Етап» і «Стан елемента»; за замовчуванням показано `failed` |
| Помилки колектора | помилки й пропуски збору: код, HTTP-статус, спроби, час. Для запуску без збору (повторна обробка) — «Запуск без збору» |
| Повторна обробка | форма повторної обробки збережених матеріалів цього завдання ([Повторна обробка](#повторна-обробка)) |

Стани елемента: `queued`, `leased`, `running`, `completed`, `retrying`, `failed`, `skipped`, `cancelled`. Елемент у `retrying` буде повторено після часу «Доступний з».

## Зупинка запуску

1. На сторінці запуску натисніть «Скасувати запуск» або в списку — «Зупинити».
2. За бажання вкажіть причину й підтвердіть («Скасувати» або «Підтвердити зупинку»).

Очікуваний результат: запуск переходить у `cancelling`, потім у `cancelled`. Повідомлення нагадує: колектор і етапи зупиняються, уже записані дані лишаються у сховищах і не відкочуються.

## Повторна обробка

Повторна обробка запускає етапи завдання для вже збережених RAW-матеріалів без нового збору. Її можна почати з вкладки «Повторна обробка» запуску, з таблиці на сторінці «Матеріали» («Повторно обробити») або з групи проблем.

1. Перевірте «Завдання» — етапи якого завдання виконати.
2. «Сховище RAW (connection_id)» — підключення, де лежать збережені матеріали.
3. «Почати з етапу» — ідентифікатор етапу, наприклад `extract-products`; порожньо — етапи після збору, як для нового збору.
4. Що обробити:
   - з вкладки запуску — «Збережені з» / «Збережені до» (RFC 3339) і за потреби точний вибір «RAW object_ids» або «observation_ids»;
   - зі сторінки «Матеріали» — поле «Що обробити»: усі збережені спостереження матеріалу, лише цей збережений RAW або лише це спостереження.
5. За потреби — «Причина» і «Тестовий режим (без запису в робочі дані)».
6. Натисніть «Обробити повторно».

Очікуваний результат: відкривається сторінка нового запуску з тригером `reprocess`; вкладка «Помилки колектора» показує «Запуск без збору».
