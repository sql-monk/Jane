# Огляд Jane

Jane — модульна платформа, яка отримує матеріали із сайтів і Telegram-каналів, витягує з них структуровані сутності й зберігає RAW та результати в обрані сховища. Кожен модуль має власний версіонований API, конфігурацію й сховище та працює окремо; Orchestrator поєднує модулі в завдання з розкладом.

Проєкт названо на честь докторки Джейн Гудолл; він не пов'язаний із Jane Goodall Institute.

## Для чого Jane

Користувач задає, звідки брати матеріали, які сутності потрібні, як їх обробити й коли виконувати. Типові задачі:

- зібрати повний каталог товарів сайту, а окремим завданням за розкладом перевіряти лише ціну й наявність;
- читати Telegram-канал, витягувати з повідомлень події й оновлювати їх після редагування повідомлення;
- підключити нове джерело: LLM досліджує вибірку сторінок і пропонує правила колектора та екстрактор, які користувач перевіряє й активує.

Вимоги до платформи — [технічне завдання](../../TECHNICAL_SPECIFICATION.md); терміни — [глосарій](glossary.md).

## Як виглядає робота

Завдання — це ланцюжок етапів: перший етап збирає матеріали колектором, наступні передають їх обробникам. Ланцюжок може розгалужуватися: одну сторінку можна водночас зберегти як RAW і передати екстрактору, а результат екстрактора — у сховище сутностей.

```text
Колектор (Web або Telegram)
  ├── Storage: збереження RAW
  └── Екстрактор (Handler Runtime)
        └── Storage: збереження сутностей
```

Етапи виконує Orchestrator: він викликає колектор, отримує матеріали й сам передає їх кожному наступному обробнику. Колектори й обробники одне одного не викликають. Докладно — [архітектура](../architecture/README.md) і [виконання завдання](../architecture/task-execution.md).

## Можливості

| Область | Що доступно |
|---|---|
| Вебджерела | явний список URL, рекурсивний обхід, Sitemap і Sitemap Index, RSS/Atom, сторінки категорій і пагінації, шаблони URL, API/JSON сайту; стратегії комбінуються в одних правилах колектора |
| Telegram | історія каналу, нові повідомлення й редагування; реальний Telegram — через обліковий запис користувача |
| Екстрактори | Python-пакети, які Handler Runtime виконує в контейнерній пісочниці з обмеженнями часу, ресурсів і мережі |
| Збереження | RAW і сутності в PostgreSQL, SQL Server, MongoDB, MinIO, S3 або файловій системі; сховище змінюється без зміни колектора чи екстрактора. У прикладах сутності лежать у MongoDB (колекція на тип), RAW — у файлах ([ADR-0011](../adr/0011-data-placement.md)) |
| Часткові оновлення | результат із частиною полів оновлює лише ці поля; запізніле спостереження не замінює новіше |
| Репозиторій пакетів | незмінні версії пакетів обробників і правил колекторів, тести, походження, форки, порівняння й перенесення змін батька за командою |
| LLM | етап ланцюжка через LLM gateway; бюджети й облік витрат; Assistant готує джерела й вдосконалює екстрактори на проблемних прикладах |
| Невідомі сторінки | передаються LLM лише за ввімкненої опції `forward_unknown_to_llm` джерела або завдання |
| Ліміти | паралельність, частота, глибина, тайм-аути, повтори, розміри й бюджети задаються конфігурацією на рівнях платформи, джерела, завдання й етапу |
| Адміністрування | Admin UI: джерела, завдання, пакети, результати, помилки, витрати |

Модулі та їхні залежності — [каталог модулів](../components/README.md).

## Чого Jane не робить

- Колектори й екстрактори не записують бізнес-результати в бази: це робить окремий етап Storage.
- Пакет у репозиторії не застосовується автоматично до всіх матеріалів: етап завдання явно посилається на версію пакета, а прив'язки обмежують, до яких URL він застосовується.
- Зміни батьківського пакета не потрапляють у форк самі: їх переносять лише за явною командою.

Поточні обмеження реалізації та неперевірені сценарії — [обмеження](limitations.md).
