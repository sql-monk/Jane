## Модулі та ролі

| Термін | Значення |
|---|---|
| Модуль | Окремо запусковий сервіс, бібліотека або набір контрактів Jane; перелік — [каталог модулів](../components/README.md) |
| Колектор | Модуль, який отримує матеріали з джерела й повертає їх із метаданими за контрактом `collector.v1`; бізнес-результатів не зберігає. Реалізації: Web Collector, Telegram Collector |
| Обробник | Модуль, який виконує один етап над переданими даними за контрактом `handler.v1`: збереження, витягування, виклик LLM або перетворення. Реалізації: Storage, Handler Runtime, LLM gateway |
| Екстрактор | Пакет обробника виду `extractor`: Python-код, що витягує сутності з матеріалу. Сам екстрактор не є сервісом — його код виконує Handler Runtime |
| Orchestrator | Сервіс координації: зберігає джерела й завдання, виконує запуски за розкладом, викликає колектори й обробники та передає дані між етапами |
| Registry | Репозиторій пакетів обробників і правил колекторів (`registry.v1`) |
| Storage | Обробник збереження: записує RAW і сутності в цільові сховища через адаптери (`handler.v1`) і віддає їх для читання (`storage.v1`) |
| Handler Runtime | Обробник, що виконує Python-екстрактори й перетворення в контейнерній пісочниці |
| LLM gateway | Обробник і API викликів моделей (`llm.v1`, `handler.v1`): провайдери, бюджети, облік витрат |
| Assistant | Сервіс координації, який за допомогою LLM досліджує нове джерело, готує правила й екстрактори та вдосконалює їх (`assistant.v1`) |
| Admin UI | Вебзастосунок оператора (`web/admin`); власних даних не має, працює через API сервісів |
| Виконавець | Сервіс, якого Orchestrator викликає під час запуску, з роллю `collector`, `handler`, `storage_read`, `registry`, `llm` або `assistant` (налаштування `JANE_ORCHESTRATOR_EXECUTORS`) |
| Автономність | Можливість запустити й використати модуль без Orchestrator та інших модулів, крім його обов'язкових залежностей |

## Джерела й матеріали

| Термін | Значення |
|---|---|
| Джерело | Сайт, Telegram-канал або інше зовнішнє місце отримання даних; в Orchestrator — документ `source` (`source.schema.json`) |
| Правила колектора | Пакет виду `collector-rules`: межі обходу, стратегії пошуку, `robots.txt`, дедуплікація, розділи сайту |
| Стратегія пошуку | Спосіб знайти URL вебджерела: `seed_list`, `recursive`, `sitemap`, `feed`, `listing`, `url_template`, `api_feed`. Тип `llm_explore` зарезервовано, колектор його не виконує |
| Збір (collection) | Тривала операція колектора, яка видає потік матеріалів із курсором (`POST /v1/collections`) |
| Матеріал | Отриманий колектором вміст із метаданими: джерело, посилання, час отримання й публікації, формат, ревізія (`material.schema.json`) |
| Спостереження | Одне отримання матеріалу. Той самий матеріал (`material_id`) при повторному отриманні — нове спостереження з новим `observation_id` |
| RAW | Оригінальний вміст матеріалу до перетворень; зберігається окремим етапом Storage |
| Невідомий матеріал | Матеріал, якому не відповідає жоден прив'язаний обробник; LLM отримує його лише за `forward_unknown_to_llm: true` |
| Посилання на вміст | `ContentRef`: великий вміст передається не в тілі відповіді, а посиланням на blob (`content-ref.schema.json`) |

## Завдання та виконання

| Термін | Значення |
|---|---|
| Завдання | Налаштований процес збору й обробки: джерело або список URL, етапи, умови, розклад, ліміти (`task-config.schema.json`) |
| Етап | Крок завдання: один етап `collect` і довільна кількість етапів `handler`. Етап посилається на конкретну версію пакета |
| Ребро етапу | Вхід етапу (`inputs`): з якого етапу брати дані, що саме (`select`) і за якої умови (`when`) |
| Прив'язка | Умова застосування обробника до матеріалів (`bindings`), наприклад шаблон URL `*/product/*` |
| Розклад | Коли запускати завдання: `manual`, `once`, `cron`, `interval`; поведінка при активному запуску — `overlap` |
| Запуск (run) | Одне виконання завдання; асинхронна операція зі станом `queued`, `running`, `cancelling`, `succeeded`, `failed`, `cancelled` |
| Елемент етапу | Одиниця роботи запуску: один матеріал або результат на одному етапі; має власний стан і лічильник спроб |
| Повторна обробка | Новий запуск над уже збереженими RAW (`POST /v1/reprocessing`), за потреби з етапу `from_stage` |
| Група проблем | Згруповані матеріали з результатом `unrecognized` або `failed` за джерелом і характером проблеми — вхід для вдосконалення екстрактора |
| Вдосконалення | Сесія Assistant, у якій LLM готує нову версію екстрактора на проблемних прикладах і перевіряє її тестами |

## Пакети й репозиторій

| Термін | Значення |
|---|---|
| Пакет обробника | Версіонований архів із маніфестом `jane-package.json`, кодом або описом виконання, схемами, тестами й походженням. Види (`kind`): `extractor`, `storage`, `llm`, `transform`, `collector-rules` |
| Версія пакета | Незмінна версія SemVer із дайджестом архіву (`sha256:…`); статуси життєвого циклу ведуться в Registry |
| Дайджест | SHA-256 канонічного архіву пакета; етап завдання фіксує версію й дайджест |
| Форк | Незалежна копія пакета з посиланням на батьківський пакет і вихідну версію; зміни батька переносяться лише явною командою |
| Профіль виконання | Середовище коду екстрактора в Handler Runtime, наприклад `python-extractor@1` |
| Походження | Хто й як створив версію (`provenance`): людина або LLM, автори, опис змін |

Формат і життєвий цикл пакетів — [довідник пакетів](../reference/packages/README.md).

## Дані та збереження

| Термін | Значення |
|---|---|
| Сутність | Об'єкт із набором полів і ключем, наприклад товар (`product`) або подія (`event`) (`entity.schema.json`) |
| Тип сутності | `entity_type`, який обирає екстрактор; разом із ключем ідентифікує сутність. Товари реальних сайтів мають типи груп `product_*`, оголошення — `ad_*` — [типи сутностей](../reference/entity-types.md) |
| Ключ сутності | Природний ключ із полів `key_fields` пакета; Storage зводить його до `canonical_key` |
| Часткове оновлення | Результат із `completeness: partial` оновлює лише передані поля; пропущене поле не видаляється |
| Порядок спостережень | Порядок `observed_at → sequence → observation_id`; запізніле значення потрапляє лише в історію |
| Підключення | Іменований опис цільового сховища, провайдера LLM або облікового запису (`connection.schema.json`): параметри й посилання на секрети, без самих секретів |
| Адаптер сховища | Реалізація запису й читання для одного типу сховища в Storage: files, postgres, sqlserver, mongodb, minio, s3 |
| Власність даних | Кожен модуль володіє власним сховищем; інші модулі отримують ці дані лише через API — [власність даних](../architecture/data-ownership.md) |

## API та надійність

| Термін | Значення |
|---|---|
| Job | Стан тривалої операції: API повертає `202` і `job_id`, стан читається `GET /v1/jobs/{job_id}` |
| Ключ ідемпотентності | Заголовок `Idempotency-Key`: повтор того самого запиту повертає збережену відповідь замість повторної дії |
| `delivery_key` | Ключ доставки елемента етапу обробнику; повтор із тим самим ключем повертає збережений результат (`duplicate: true`) |
| Дубль | Повторна технічна доставка того самого результату; не створює нових записів. Повторне отримання з джерела — не дубль, а нове спостереження |
| Lease | Тимчасове право воркера Orchestrator на елемент етапу; після його закінчення елемент підхоплює інший воркер |
| Помилка API | Відповідь `application/problem+json` з кодом (`code`) і ознакою `retryable` — [модель помилок](../../contracts/docs/errors.md) |

## Безпека й налаштування

| Термін | Значення |
|---|---|
| Ключ API | Секрет викликача в заголовку `Authorization: Bearer`; сервіс зберігає лише його SHA-256 і набір дозволів (scopes) |
| Посилання на секрет | Рядок `env:<змінна>` або `file:<шлях>` у `secret_refs` підключення; значення секрету читає лише сервіс, який його використовує |
| Ліміти | Числові обмеження виконання (`limits.schema.json`): частота, паралельність, глибина, тайм-аути, повтори, розміри, бюджети. Успадковуються: платформа → джерело → завдання → етап |
| Профіль лімітів | Набір лімітів платформи для середовища: `dev-laptop`, `ci`, `single-node` (`deploy/profiles/`) |
| Dev-стек | Набір контейнерів `infra/compose.yaml` для розробки й перевірок; запускається `just up` |
