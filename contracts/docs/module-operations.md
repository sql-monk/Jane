# Моніторинг і конфігурація модулів

Кожен модуль надає [Operations API](../openapi/operations.v1.yaml), установлений через `jane-kit`. Адмінка звертається до конкретного модуля; оркестратор для цього API не потрібний.

## Конфігурація

`GET /v1/configuration` повертає типи й обмеження полів, активне `value`, початкове `inherited_value`, збережене `configured_value`, `overrides`, `revision`, `pending_restart` і ETag. Секрети, інфраструктурні адреси та політики доступу не входять до переліку редагування.

`PUT /v1/configuration` повністю замінює перевизначення. Відсутній ключ успадковує початкову конфігурацію; `values: {}` скидає всі перевизначення. Заголовок `If-Match` із попереднього GET обов’язковий: без нього відповідь 428, після сторонньої зміни — 412. Невідомі поля, неправильні типи, порушення зв’язків між параметрами й жорстких меж повертають 422.

```json
{
  "values": {
    "settings.render_enabled": true,
    "limits.concurrency.max_parallel_fetches": 4
  }
}
```

Зміни застосовуються під час наступного старту модуля. API не перезапускає сервіс і не змінює конфігурацію поточних запитів. `pending_restart` враховує також видалення вже застосованих перевизначень. Налаштування модуля перекривають початкові значення, але не обходять жорсткі межі. Ліміти джерела, завдання та етапу зберігають власне успадкування; їх показує `/v1/limits/effective` оркестратора.

Scopes: `modules:read` або `modules:write` для читання, `modules:write` для збереження. У dev-стеку ці права додані тільки адміністратору. Журнал `changes` зберігає ревізію, час, ім’я актора й документ конфігурації.

## Історія вимірювань

`GET /v1/telemetry?since=<UTC>&until=<UTC>&limit=<кількість>` повертає визначення метрик і часові точки. Частота вимірювання, строк зберігання та максимум точок налаштовуються модулем. Для великої історії API вибирає рівномірно розташовані точки зі збереженням першої та останньої, не усереднює різні процеси чи відсутні значення. `resolution_seconds` передає номінальний інтервал прорідженої історії; графік враховує його, щоб звичайне прорідження не виглядало як зупинка збору. `sample_interval_seconds` залишається фактичною частотою вимірювань модуля.

| Показник | Що вимірюється |
|---|---|
| API-запити та 5xx за секунду | Різниця лічильників між вимірюваннями; health/info/configuration/telemetry виключені |
| Середній час API-запиту | Різниця сум тривалостей, поділена на кількість запитів у тому самому інтервалі |
| Прийняті матеріали | Матеріали, прийняті оркестратором за секунду |
| Завершені елементи етапів | Усі результати етапів оркестратора, включно з помилками; це не кількість сутностей |
| Підтвердження запису | `WriteAck` сховища за секунду |
| LLM-запити | Виклики провайдера за секунду |
| Черга, активні елементи, вік черги | Поточні рядки власної таблиці `items` оркестратора |

`null` означає недоступне вимірювання, а не нуль. Перший rate після старту та середній час без запитів невідомі. Час передається в UTC з `Z`. `instance_id` відрізняє процеси; графік розривається після перезапуску, пропуску вимірювань або `null`. Лічильники процесу не є статистикою всього кластера.

## Зберігання й споживачі

Конфігурація, журнал змін і історія зберігаються у власному `operations.sqlite3`. Каталог задає `<PREFIX>OPERATIONS_DIR`; стандартно `.jane/operations/<service>`. У Compose кожен модуль має окремий том `/var/lib/jane-operations`. Різні вузли мають власні каталоги; спільний SQLite на мережевому диску не є сховищем метрик кластера.

| Реалізація | Споживач |
|---|---|
| Web Collector, Telegram Collector, Runtime, Storage, Registry, LLM, Assistant, Orchestrator через `jane_kit.service.create_app` | Адмінка через згенерований клієнт `operations`; сторонні застосунки через HTTP |

Чинні сім сервісних API та Python Protocol-и зворотно сумісні. Operations описує додатковий спільний інтерфейс.
