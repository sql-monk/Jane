# ADR-0002 — Версії пакетів у Registry

Дата: 2026-10-11. Основа: `91876d1`. Стан: опис реалізованого рішення; новий текст у review.

## Проблема

ТЗ §7 вимагає версій, тестів, походження й незалежних форків. Виконання має посилатися на точний артефакт, щоб зміна пакета не змінювала вже налаштоване завдання непомітно.

## Розглянуті підходи

| Підхід | Наслідок |
|---|---|
| Змінний каталог коду | Простий локальний доступ, складні відтворення й аудит |
| Незмінні версії з API | Контроль публікації, фіксовані артефакти та export |

## Рішення

Registry зберігає метадані у власному PostgreSQL backend, а артефакти — у content-addressed S3/MinIO або файловому blob-сховищі. Пакет має маніфест, точну версію, схеми, тести й походження. Форк є окремим пакетом; перенесення змін батьківської версії є явною операцією. API export дає артефакт для автономного використання.

## Наслідки

Завдання фіксує версію пакета. Новий код публікується новою версією. Для довговічного Registry потрібні збережені метадані й артефакти; memory backend метаданих придатний для одного тестового процесу. Локальний артефакт може усунути віддалений Registry з runtime-сценарію.
