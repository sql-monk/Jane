# WP-14. Профілі лімітів і експлуатація

**Гілка:** `wp/14-limit-profiles-ops` · **Ревізія реалізації:** `d6fb478` · **База на старті:** `05261b4` · **Стан:** blocked

## Результат

- У [`deploy/profiles/`](../../deploy/profiles/README.md) розміщено три schema-valid документи
  `PlatformLimits` (`dev-laptop`, `ci`, `single-node`) і кросплатформний валідатор. Числа без
  змін перенесено з довідкових прикладів WP-00. Це **кандидати**, не виміряні профілі.
- [`docs/operations/README.md`](../operations/README.md) описує автономний і спільний запуск,
  конфігурацію лімітів та оновлення/міграції. Окремо описано
  [резервування й відновлення](../operations/backup-restore.md) та
  [протокол вимірювання](../operations/limits-validation.md).
- [`examples/README.md`](../../examples/README.md) дає порядок для каталогу товарів, окремої
  перевірки цін і подій Telegram на основі контрактних JSON-зразків, із чітким переліком
  потрібних пакетів, підключень і зовнішнього доступу.

Три пропуски контрактних тестів: два тести LLM потребують PostgreSQL dev-стеку,

## Конфігурація й ліміти

| Параметр | Джерело | Статус |
|---|---|---|
| `JANE_ORCHESTRATOR_LIMITS_FILE` | `deploy/profiles/<profile>.json` лише для першого заповнення БД | інтерфейс підтверджений кодом, застосування профілю на стеку не тестовано |
| `PUT /v1/limits/platform` | чинний документ + `If-Match` ETag | шлях для зміни без перезбирання; WP-14 не виконував його на реальному API |
| Ліміти source/task/stage | документи джерел/завдань, `GET /v1/limits/effective` | успадкування й hard caps за контрактом; профілі не виміряно |

## Відомі обмеження та неперевірені інтеграції

ADR-0007 залишає людині підтвердження реальних цільових середовищ. `infra/compose.yaml`
містить dev-залежності й testsite, а не всі застосунки. Наведені в контрактах product/price
package digest є демонстраційними. Сценарії з реальними сайтами, LLM-провайдером, Telegram,
SQL Server/MongoDB/S3 і відновленням backup **не перевірено на реальному сервісі**.
