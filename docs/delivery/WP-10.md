Не зроблено / відхилення:
- **Реальний виклик Anthropic не виконувався** — ключа немає: «не перевірено на реальному сервісі». Форма запиту
  (заголовки, `system`/`messages`, `output_config.format`, розбір `usage`/`stop_reason`) перевірена тестом проти
  локального HTTP-замінника Messages API.
- Офіційний SDK `anthropic` спершу був підключений, але його 1.x тягне `httpx2`; у спільному uv workspace це
  перемкнуло `starlette.testclient.TestClient` на `httpx2` для всіх сервісів і зламало mypy тестів jane-kit
  (`ContractClient` очікує `httpx.Client`). Тому адаптер пише Messages API напряму через httpx.
- Публікація пакета в registry перевірена лише на моку з `registry.v1.yaml` (WP-05 паралельно).
- Автентифікація (`api_key`/`jwt`, ADR-0005) не реалізована — сервіс, як і шаблон, лише повідомляє `auth_mode`.

## Відомі обмеження
- Вартість до виклику оцінюється (символи / `gateway.chars_per_token_estimate`, типово 2.0, + `max_output_tokens`), тому
  виклик відхиляється, коли оцінка не вміщується в залишок, навіть якщо фактична вартість вмістилася б;
  `status.exhausted` = «витрачено ≥ ліміту».
- Оцінка не гарантує верхньої межі: якщо токенізатор провайдера дає більше токенів, ніж оцінка (напр. щільний текст),
  фактична вартість виклику може перевищити резерв, і `витрачено` може перевищити ліміт на цю різницю для
  викликів, що йшли одночасно; наступні виклики тоді зупиняються. Жорсткіша межа — менший `chars_per_token_estimate`.
- `temperature` не передається провайдеру `anthropic` (нові моделі не приймають параметрів семплювання).
- Резерв екземпляра, що впав під час виклику, списується за оцінкою через `reservation_ttl_seconds` (консервативно).
- Скасування job з іншого екземпляра лише позначає `cancelling`; перервати виконання може тільки екземпляр, що його виконує.
- Відображення виходу LLM на сутності — конвенція сервісу (масив `<entity_type>s`, ключ `message` → `material_id`), у контракті не описана.
- Blob `s3://` без `download_url` не читається (потрібен `download_url` або `file://`).
- Бюджет з періодом `run` без `run_id` у scope пропускається (з попередженням у журналі).
- `vault:` у `secret_refs` не підтримано (розв'язується як «не знайдено»).
- Автентифікація запитів не реалізована (`auth_mode` лише звітується); ризик витоку секретів через підключення
  обмежено політикою секретів (рев'ю 1).

## Неперевірені інтеграції
- Anthropic Messages API — **не перевірено на реальному сервісі** (немає ключа); лише локальний замінник API.
- Registry (WP-05): публікація — лише проти моку з `registry.v1.yaml`; завантаження архіву — проти тестового
  замінника на шляху `…/versions/{v}/archive` (мок з контракту не повертає zip). Канонічний дайджест локального каталогу

## Доповнення WP-10d: ідентичність пакета при влучанні в кеш

`PackageLoader` тепер розділяє кеш архівів, переданих у запиті, та пакети, знайдені
локально або в registry. При посиланні без архіву кеш використовується лише для того
самого `package_id`, версії та digest. Архів запиту читається й перевіряється щоразу;
кеш пропускає тільки повторне розпакування тих самих байтів. Це усуває випадок,
коли посилання на 1.0.0 з дайджестом кешованої 1.0.1 виконувало 1.0.1.

Незалежний рецензент перевірив логіку й контракт `PackageRef`. Три файли
`services/llm/` перенесено з `wp/10c-package-cache-identity` байт у байт у гілку
власника WP-10. Зміну e2e-тесту передано WP-13 окремо.
