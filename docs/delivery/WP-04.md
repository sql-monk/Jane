**Запити WP-09 і WP-11** — зроблено й перевірено тестами:
1. Однаковий `Idempotency-Key` на `POST /v1/collections` → той самий job (`Idempotency-Replayed: true`), зокрема
   через інший екземпляр (ключі в спільному SQLite) — `test_same_idempotency_key_returns_the_same_job`,
   `test_two_instances_share_state_and_take_over_after_kill`, контрактний тест.
2. `limits.queue.max_unacked_materials` із запиту призупиняє збір — `test_backpressure_limit_from_the_request`
   (3 із запиту, `effective_limits` показує 3), `hard_caps` платформи обмежують запит — `test_platform_limits_and_hard_caps_from_environment`.
3. Правила без registry — inline або локальний пакет `RULES_DIR` — `test_third_party_app_uses_the_collector_without_orchestrator`.
4. WP-11: вміст inline (`content_delivery: inline`; текст повідомлення завжди inline в `auto` до `inline_max_bytes`) —
   `test_content_delivery_blob_and_inline`; `stats.by_strategy` (`telegram_history` / `telegram_updates`) —
   `test_history_is_collected_as_valid_materials`, `test_incremental_collects_only_new_messages`.

Не зроблено / свідомо:
- Реальний Telegram: тестового облікового запису немає → адаптер Telethon **не перевірено на реальному сервісі**.
- Blob у MinIO/S3 — лише транзитний каталог (`file://`), як у WP-02.
- Автентифікація запитів до API не перевіряється (`auth_mode=none`, як у шаблоні jane-kit).
- Інтерактивний вхід в обліковий запис (код із SMS) — поза сервісом: потрібна готова сесія в секреті.

## Відомі обмеження
- Стан — SQLite на одному вузлі: кілька екземплярів лише зі спільним `STATE_DIR` на одному хості (ADR-0007: v1
  одновузловий). Процес, заморожений *усередині* транзакції запису, блокує файл для всіх (lease цього не
  лікує); інші екземпляри тоді відповідають 503 `service_unavailable` (retryable) замість 500. Тест
  «завислого власника» заморожує процес поза транзакцією (під час backpressure).
- Канали одного збору читаються послідовно.
- `revision.content_sha256` — хеш тексту; зміна лише медіа видно за `sequence`, не за хешем.
- Таблиця відомих ревізій росте на одне повідомлення каналу (очищується `DELETE /v1/states/{state_key}`).
- Невідомі поля `limits` груп `jobs`/`idempotency`/`page`/`collector` у запиті ігноруються (вони не в контракті).
- Код `ContractSchemas`/`RulesLoader` адаптовано з WP-02 (`services/web-collector`), бо спільного місця в
  `jane-kit` для нього немає (див. запити).

## Неперевірені інтеграції
- **Telegram (Telethon) — не перевірено на реальному сервісі**: немає тестового облікового запису; адаптер
  написано за API Telethon 1.x, покрито лише типами. Уся поведінка колектора перевірена на бекенді `recorded`.
- Registry (`REGISTRY_URL`) — код завантаження правил перенесено з WP-02 без окремого тесту в цьому сервісі
  (там він покритий моком registry); перевірено лише локальний пакет і inline.
- Оркестратор (WP-09) як споживач — не перевірено (його ще немає в `main`); перевірено сторонній клієнт.
