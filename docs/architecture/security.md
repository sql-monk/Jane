## Автентифікація та права

| Режим | Механізм | Використання |
|---|---|---|
| `none` | Anonymous із усіма scopes | Локальні тести; за замовчуванням лише loopback |
| `api_key` | Bearer-ключ, SHA-256 або керований secret_ref, список scopes | Ізольований dev-стенд та сервісні інтеграції |
| `jwt` | Асиметрично підписаний JWT, JWKS, issuer, audience, expiry і scopes | Розгортання з провайдером ідентичності |

Сервіси використовують спільну [реалізацію Jane Kit](../../libs/jane-kit/src/jane_kit/auth.py). Відсутність ключів, JWKS-конфігурації або відповідності маршруту scope зупиняє старт. Неприпустимий токен дає `401`, недостатні права — `403`.

Scope належить конкретній HTTP-операції, а його декларація зберігається в OpenAPI як `x-jane-scope`. [Таблиці scopes](../../libs/jane-kit/src/jane_kit/auth_scopes.py) та [контрактні перевірки](../../libs/jane-kit/tests/test_auth_scopes.py) підтримують однакові правила для всіх сервісів.

Admin підтримує ручний Bearer-вхід та OIDC Authorization Code з PKCE; конфігурація обирає режим. Код входу: [session](../../web/admin/src/auth/session.ts), [OIDC](../../web/admin/src/auth/oidc.ts).

## Підключення та секрети

Пакет визначає потребу в доступі, а підключення задає спосіб отримання секрету. Облікові дані не входять до артефакта пакета й не переносяться у форк.

| Об’єкт | Що містить |
|---|---|
| Пакет | Код, схеми, вимоги та параметри |
| Connection | Endpoint, несекретні options і secret_ref |
| Secret resolver | Значення зі змінної середовища або дозволеного файла |
| Сервісний токен | Право клієнта викликати конкретний сусідній API |

Розв’язування `env:` і `file:` реалізоване у [secrets.py](../../libs/jane-kit/src/jane_kit/secrets.py). Файловий secret resolver обмежує дозволений каталог і перевіряє шлях. API підключень повертає посилання на секрет, а не його значення.

Orchestrator синхронізує декларації підключень через `/v1/connections/{id}`. Виконавець читає значення у власному середовищі. Виконавець без керованих підключень може повернути `not_implemented`; [engine](../../services/orchestrator/src/jane_orchestrator/engine.py) обробляє це як відсутність участі у синхронізації.

## Зовнішні адреси та матеріали

- Web Collector перевіряє область обходу, мережеві адреси, robots і політику підключення.
- ContentReader приймає лише дозволені файлові корені або download hosts, перевіряє розмір і хеш.
- Storage перевіряє адреси й options цільових підключень.
- LLM перевіряє API base провайдера та відділяє матеріал джерела від інструкцій моделі.
- Assistant обмежує дослідження джерела, вибірку й витрати.

Джерела: [Web egress](../../services/web-collector/src/jane_web_collector/egress.py), [ContentReader](../../libs/jane-kit/src/jane_kit/content.py), [Storage policy](../../services/storage/src/jane_storage/policy.py), [LLM prompt](../../services/llm/src/jane_llm/prompt.py), [Assistant guards](../../services/assistant/src/jane_assistant/guards.py).

Текст сторінки або повідомлення передається як зовнішні дані. Підготовлена зміна пакета проходить версіонування й тести та активується за налаштованим режимом погодження.

## Виконання коду

Docker backend Handler Runtime створює окремий контейнер для invocation:

- мережа вимкнена;
- коренева файлова система лише для читання;
- користувач без root, `cap_drop: ALL`, `no-new-privileges`;
- пакет і входи копіюються у підготовлений робочий том;
- CPU, пам’ять, кількість процесів, час і stdout/stderr обмежені профілем;
- секрети й довільні host-томи в середовище пакета не передаються.

Параметри реалізовані у [docker_sandbox.py](../../services/handler-runtime/src/jane_handler_runtime/docker_sandbox.py). Доступ Runtime до Docker Engine є окремим привілеєм сервісу: Runtime не слід надавати ширші права вузла, ніж потрібні для керування контейнерами.

## Розгортання

Dev-проксі обслуговує HTTP, вимикає auto HTTPS і передає `/api/<service>/` потрібному сервісу. Це конкретна конфігурація [Caddyfile](../../infra/proxy/Caddyfile). Для мережевого розгортання потрібні TLS-термінація, належний auth mode, окремі сервісні scopes та обмеження доступу до баз і Docker Engine.

Рішення: [ADR-0003](../adr/0003-python-sandbox.md), [ADR-0005](../adr/0005-authentication.md), [ADR-0006](../adr/0006-managed-connections.md). Далі: [розгортання](deployment.md).
