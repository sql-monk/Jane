# Версії, архів і дайджест

Кожна опублікована версія пакета незмінна: її файли зберігаються як канонічний ZIP, а `digest` — SHA-256 цих байтів. Етап завдання посилається на точну версію й дайджест, тож виконавець завжди отримує саме те, що було перевірено. Точна реалізація архіву — [archive.py](../../../services/registry/src/jane_registry/archive.py); нормативний опис — розділ «Структура архіву» в [handler-packages.md](../../../contracts/docs/handler-packages.md).

## Номер версії

`version` — точна версія [Semantic Versioning 2.0.0](https://semver.org/) (`1.3.0`, `2.0.0-rc.1`). Діапазони й `latest` у посиланнях на пакети заборонені.

Registry не перевіряє, що нова версія більша за попередню, і не перевіряє вид зміни. Домовленість для авторів:

| Зміна | Частина версії |
|---|---|
| Несумісна зміна полів, ключів або схеми виходу | major |
| Нові поля, селектори, підтримка нових сторінок | minor |
| Виправлення без зміни контракту виходу | patch |

Порядок версій (для `latest_version`, diff і перенесення змін) — порядок SemVer: числові частини, потім передрелізи (`1.0.0-rc.1` < `1.0.0`).

## Незмінність

- Повторна публікація тієї самої версії — `409 version_exists`; виправлення можливе лише як нова версія.
- Змінюються тільки атрибути навколо версії: статус (`POST …/status`) і звіти тестів (`POST …/test-results`). Файли, маніфест і `digest` — ніколи.
- Повтор запиту публікації з тим самим заголовком `Idempotency-Key` і тим самим тілом повертає збережену відповідь (`201`), нової версії не створює.
- Архів відкликаної версії (`yanked`) залишається доступним, щоб наявні посилання не ламалися.

## Остання версія пакета

`latest_version` пакета — найбільша за SemVer версія зі статусом, відмінним від `rejected` і `yanked`. Чернетки (`draft`) теж враховуються. Пошукові поля пакета (`tags`, `entity_types`, `media_types`, `domains`) беруться з маніфесту саме цієї версії.

## Канонічний архів

Registry приймає ZIP, зібраний будь-яким способом (зі стисненням, іншими датами, записами каталогів), або JSON з маніфестом і файлами. Перед збереженням він розпаковує вміст із перевірками й перепаковує його канонічно:

- лише звичайні файли, без записів каталогів і симлінків;
- записи відсортовані за шляхом у порядку байтів;
- метод `ZIP_STORED` (без стиснення), тож байти не залежать від версії zlib;
- час кожного запису `1980-01-01 00:00:00`, права `0o100644 << 16`, `create_system = 3` (Unix);
- без extra-полів, коментарів і шифрування.

Для JSON-публікації `jane-package.json` формує сам Registry: UTF-8, відступ 2 пробіли, порядок ключів як у запиті, без ASCII-екранування, з кінцевим переносом рядка. Тому той самий набір файлів дає ті самі байти на Windows і Linux.

## Дайджест

`digest = "sha256:" + sha256(байти канонічного ZIP)`, 64 шістнадцяткові символи в нижньому регістрі. Дайджест залежить лише від шляхів і вмісту файлів, а не від того, як було зібрано вхідний ZIP.

Хто й де перевіряє дайджест:

| Місце | Перевірка |
|---|---|
| Registry, запис у blob-сховище й читання з нього | Байти об'єкта збігаються з `digest`; інакше помилка цілісності |
| `GET …/versions/{v}/archive` | Заголовки `ETag` і `X-Jane-Package-Digest` містять `digest` |
| `jane-registry export` | Байти, `ETag` і `digest` версії збігаються |
| Виконавець (`PackageRef.digest`) | Архів, отриманий за посиланням із `digest`, має той самий дайджест, інакше `digest_mismatch` |
| Звіт тестів (`report.package.digest`) | Звіт зроблено саме для цієї версії, інакше `digest_mismatch` |

Дайджести в прикладах OpenAPI й JSON-схем ілюстративні; реальний дайджест береться з відповіді Registry або обчислюється з канонічного ZIP.

## Архів локального каталогу

CLI Registry будує канонічний архів і дайджест локального пакета без запущеного сервісу. Кеші (`__pycache__`, `.pytest_cache`, `.venv`, `.git` тощо) і файли `.pyc` не пакуються; симлінк у каталозі — помилка.

```powershell
uv run --package jane-registry jane-registry archive examples/packages/examples.testsite-price-extractor --out .jane/registry-quickstart/price-1.0.0.zip
```

```text
.jane\registry-quickstart\price-1.0.0.zip  sha256:d143e1e9b7a4f3f2ea28886cc6fd37c29cb9915fce772d1a84b1ea6ea6bfa2f9
```

Той самий дайджест записано в [examples/packages.lock.json](../../../examples/packages.lock.json), і той самий Registry повертає після публікації цього каталогу (перевірено в [quickstart Registry](../../components/registry/quickstart.md)).
