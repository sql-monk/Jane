## Вимоги й порядок роботи

- [DOCUMENTATION_REQUIREMENTS.md](../../DOCUMENTATION_REQUIREMENTS.md) — зміст, структура, стиль і приймання документації.
- Скіл `jane-documentation` (`.agents/skills/jane-documentation/SKILL.md`) — порядок роботи агента.
- Факти беруться з коду, контрактів, конфігурації й тестів; [ТЗ](../../TECHNICAL_SPECIFICATION.md) — джерело вимог. Розбіжність коду й ТЗ позначається в тексті: «Розбіжність із ТЗ: …».
- `docs-archive/` — попередня документація поза навігацією; основою нового тексту не є.

## Структура

```text
docs/
├── README.md            # зміст і маршрути читання
├── overview/            # призначення, можливості, терміни, обмеження
├── getting-started/     # запуск і перший результат
├── user-guide/          # сценарії роботи через Admin UI
├── architecture/        # будова платформи, карта репозиторію
├── components/<модуль>/ # повний комплект модуля
├── reference/           # загальний індекс довідників, пакети обробників
├── development/         # цей розділ
├── operations/          # експлуатація платформи
├── diagrams/            # джерела .drawio і PNG
├── adr/                 # архітектурні рішення
├── acceptance/          # відповідність ТЗ і докази
└── delivery/            # статуси й звіти WP
```

Комплект модуля `docs/components/<модуль>/`:

| Файл | Зміст |
|---|---|
| `README.md` | Призначення, межі, тип, сценарії, автономність, навігація |
| `quickstart.md` | Незалежний запуск і перевірка: передумови, кроки, очікуваний результат, прибирання |
| `dependencies.md` | Обов'язкові й опційні залежності, версії, поведінка за недоступності |
| `configuration.md` | Параметри, змінні середовища, типові значення, ліміти, застосування змін |
| `integration.md` | Самостійне використання, композиція в Jane, заміна |
| `internals.md` | Будова, алгоритми, стани, власні дані, гарантії |
| `operations.md` | Моніторинг, оновлення, міграції, резервування, проблеми, власність даних |
| `reference/` | Довідники API й типів — генеруються |

Комплекти, що вже є: [jane-kit](../components/jane-kit/README.md), [контракти](../components/contracts/README.md).

## Оформлення

- Один заголовок H1, рівні без пропусків, унікальні заголовки; довга сторінка — зміст із посиланнями на якорі.
- Чистий Markdown без сирого HTML; посилання відносні з `/`.
- Таблиці компактні: один рядок — одне поняття; довгі пояснення — під таблицею.
- Кожен блок коду має мову: команди `uv`, `just`, Docker — `powershell`; Bash-специфічне — `bash` з підписом; `python`, `json`, `yaml`, `toml`, `sql`, `typescript`; дерева й вивід — `text`. Команда й вивід — в окремих блоках; вивід — лише з реального запуску, уривок позначається.
- Перед командою очищення — що саме вона видаляє.
- Мова пояснень — українська; ідентифікатори й сигнатури — як у коді.

## Діаграми

- Джерело — `docs/diagrams/<розділ>/<назва>.drawio`; поруч обов'язкові `<назва>.light.png` і `<назва>.dark.png` з прозорим фоном.
- Стиль — як у [composition.drawio](../diagrams/platform/composition.drawio): `html=0`, перенос рядка — `&#xa;`, кольори `light-dark(#світлий,#темний)`, палітра за ролями (координація, колектори, обробники, репозиторій, клієнти, зовнішнє), різні лінії для виклику API, опційної залежності й даних, легенда за кількох стилів.
- Вставка в Markdown — світлий і темний PNG підряд (`#gh-light-mode-only`, `#gh-dark-mode-only`) і рядок із посиланнями на обидва PNG та `.drawio`.

Скрипт [scripts/docs_diagrams.py](../../scripts/docs_diagrams.py) (uv-скрипт із залежністю `pillow`):

| Команда | Що робить | Потребує draw.io |
|---|---|---|
| `uv run --script scripts/docs_diagrams.py lint [файли]` | Розбирає джерела: ребра посилаються на наявні вузли, немає HTML-підписів, є вузли | ні |
| `uv run --script scripts/docs_diagrams.py export [файли]` | Рендерить світлу й темну теми з прозорим фоном, перевіряє PNG, записує SHA-256 джерела й PNG у `docs/diagrams/checksums.json` | так |
| `uv run --script scripts/docs_diagrams.py check` | Без draw.io: джерела, обидва PNG (RGBA, прозорий фон, видимий вміст, однаковий розмір) і збіг контрольних сум — джерело, змінене без нового експорту, не проходить | ні |

draw.io шукається в `JANE_DRAWIO`, далі `C:\Program Files\draw.io\draw.io.exe` (Windows) або `drawio` у `PATH` (Linux без дисплея — під `xvfb-run`). Тайм-аут одного експорту — `JANE_DRAWIO_TIMEOUT_S` (типово 90 с). Експорт не запускають паралельно кілька процесів.

Перевірка діаграм цього розділу (уривок):

```powershell
uv run --script scripts/docs_diagrams.py lint docs/diagrams/development/ci-pipeline.drawio
```

```text
ok   development/ci-pipeline
```

## Перевірка Markdown

```powershell
uv run --no-project python scripts/docs_check.py [файли або каталоги]
```

Без аргументів перевіряє `README.md`, `DEVELOPMENT.md`, увесь `docs/` і README модулів (крім `docs-archive/`). Перевірки:

- локальні посилання ведуть на наявні файли, `#якір` — на наявний заголовок (правила якорів GitHub), `#L<n>` — на наявний рядок;
- кожен блок коду має мову й закритий; немає сирого HTML поза кодом;
- рівно один H1, без пропусків рівнів і дублікатів заголовків;
- за світлим PNG `#gh-light-mode-only` іде його темна пара.

Код виходу `1`, якщо є хоч одна помилка. Скрипт не перевіряє візуальний рендер: таблиці, підсвічування й діаграми переглядають окремо в цільовому переглядачі.

## Довідники

Довідники API й типів модулів (`docs/components/<модуль>/reference/`, `docs/reference/`) генеруються з коду й контрактів скриптом координатора:

```powershell
uv run --script scripts/docs_reference.py generate
uv run --script scripts/docs_reference.py check
```

`generate` записує довідники, `check` перевіряє, що згенеровані файли актуальні. Ці команди веде координатор, у межах цього розділу вони не запускались. Вручну довідники не редагують; автори сторінок посилаються лише на `README.md` довідників.

## Перевірка прикладів

- Кожну інструкцію виконують насправді й указують дату, ОС і ревізію; неперевірене позначають «не перевірено» з причиною.
- Сервіси слухають `127.0.0.1` на вільних портах; стек — у власному compose-проєкті (`just up --project <ім'я>`), після роботи — `just down -v --project <ім'я>`.
- Тимчасовий стан (`.jane/<сервіс>/`, тимчасові каталоги) прибирають.
- Реальні секрети не читають і не вводять; для LLM — провайдер `fake`.
