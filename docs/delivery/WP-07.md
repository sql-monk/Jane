## Відомі обмеження

- У пам'яті екземпляра: кеш ключів ідемпотентності (лише для 422/409), результати `GET /v1/invocations/{id}`,
  підключення, додані через `PUT` (з файла — на всіх екземплярах). Стійка дедуплікація — у сховищі.
- Однаковий порядок спостереження (та сама `observation`, повторна обробка RAW новою версією екстрактора з новим
  `delivery_key`) за контрактом не «новіший» → поля вже відомі залишаються, нові поля застосовуються.
- Пакет з `entry.history: false` відхиляється (422 / помилка завантаження): історія потрібна для перевірки завершеності доставки.
- Файловий адаптер: `list_*` сканують каталоги (O(n)); зняття застарілого блокування (`lock_stale_ms`) небезпечне,
  якщо коміт триває довше за цей поріг.
- Читальний API бачить лише простір імен підключення (`params.prefix` / `table_prefix` / `schema` підключення);
  дані, записані з іншим префіксом етапу, через storage.v1 не видно (контракт не має такого параметра).
- `GET /v1/objects/{id}` для PostgreSQL віддає Material з inline-вмістом (до `transfer.inline_max_bytes`), бо
  `ContentRef.uri` допускає лише `s3://` і `file://`; більші об'єкти — без `material`, вміст — `/content`.
- `vault:` у `secret_refs` не підтримується (ADR-0006: опційний провайдер).

## Неперевірені інтеграції

- Публікація пакетів — лише на моку registry з контракту (WP-05 не готовий).
- Читання `s3://`-матеріалів через транзитне підключення (`JANE_STORAGE_TRANSIT_CONNECTION_ID`) і `download_url` —
  не перевірено на реальному MinIO/S3 (є код, тестів проти сервісу немає).
- Інтеграції з оркестратором (WP-09) і колекторами — лише через контрактні приклади.

| Налаштування | Типово | Правило |
|---|---|---|
| `JANE_STORAGE_SECRET_ENV_PREFIX` | `JANE_SECRET_` | `env:VAR` — лише змінні з префіксом (сам префікс без суфікса — ні); порожнє значення вимикає `env:` |
| `JANE_STORAGE_SECRET_FILES_DIR` | `/run/secrets` | `file:<path>` — лише файл усередині каталогу; шлях спершу розв'язується (`..`, symlink не виходять за межі), читається саме розв'язаний файл; порожнє значення вимикає `file:` |
| `JANE_STORAGE_CONNECTION_HOST_ALLOWLIST` | `[]` | JSON-список `hostname` (будь-який порт) або `hostname:port`; некоректний запис — помилка старту. Порожній список: будь-яке підключення з мережевою адресою відхиляється |
| — | — | `vault:` і невідомі схеми відхиляються |

Які параметри перевіряються (`KIND_ADDRESSES` + `GENERIC_ADDRESS_KEYS` у `policy.py`), з урахуванням
типових значень адаптерів (відсутній `host` = `localhost`, тобто теж має бути в allowlist):

| kind | Параметри → ефективна адреса |
|---|---|
| `postgresql` | `host` (типово `localhost`) + `port` (5432); `host:port` у `host` теж розбирається |
| `sqlserver` | `host` (`localhost`) + `port` (1433) |
| `mongodb` | `host` (`localhost`) + `port` (27017); `host` може бути рядком підключення `mongodb://h1[:p],h2[:p]/…` (перевіряються **всі** хости, порт за замовчуванням — `params.port`) або `mongodb+srv://h` (перевіряється `h`, лише запис allowlist без порту) |
| `s3` | `endpoint` (лише `http`/`https`, порт 80/443 за схемою); власний `endpoint` вимагає `addressing_style: path`; без `endpoint` перевіряється фактичний host botocore для `bucket`/`region`/`addressing_style` (в `us-east-1` це часто `bucket.s3.amazonaws.com` або `s3.amazonaws.com`, а не `s3.us-east-1.amazonaws.com`) |
| `minio` | `endpoint` (без нього адаптер не відкривається — адреси немає); власний `endpoint` вимагає `addressing_style: path` (типове значення адаптера) |
| `filesystem` | немає мережевої адреси |
| будь-який kind (і невідомі ядру адаптери) | `host`, `hosts`, `hostname`, `server`, `address`, `endpoint`, `endpoint_url`, `url`, `uri`, `dsn`, `connection_string`, `base_url`, `api_base` (крім уже розібраних правилом kind): `hostname[:port]`, `scheme://host[:port][,…][/…]` або список; що не розбирається (напр. libpq `host=x port=y`) — відхиляється |

Суворий розбір: без userinfo `@`, `\`, пробілів/керівних символів, `%` у хості, кінцевої крапки, IPv6-літералів,
шляхів Unix-сокетів, ком (крім рядка MongoDB), порт 1…65535; хост порівнюється в нижньому регістрі.

`JANE_STORAGE_CONTENT_FILES_DIR` і `JANE_STORAGE_DOWNLOAD_HOST_ALLOWLIST` у цих compose-файлах поки
**не задавати**: немає змонтованого спільного транзитного тому або затвердженого HTTP producer-хоста.
Порожній список для download — типовий. Якщо `file://` знадобиться, власник compose має додати спільний том
із producer-ом та встановити шлях усередині обох контейнерів; якщо `download_url` знадобиться, додати лише
конкретний `hostname[:port]` producer-а.

## Виправлення після рев'ю 1 (WP-07b)

1. `ConnectionPolicy` тепер відхиляє `s3` або `minio` з власним `params.endpoint`, якщо
   `addressing_style` дорівнює `virtual`/`auto`. Для `s3` відсутнє значення також означає `auto` й
   відхиляється; для `minio` відсутнє значення означає безпечне типове `path`. Помилка 422 має
   `errors[].pointer=/params/addressing_style` і `code=host_not_allowed`. Це запобігає відправленню
   секретів на `<bucket>.<endpoint host>` поза allowlist. E2E S3 уже задає `path`; MinIO використовує
   його типово. Приклади з власним endpoint і `path` лишаються прийнятними.
2. `ContentReader` більше не вставляє `ref.uri` у помилку, яку бачить викликач. `s3://` з query або
   fragment відхиляється до транзитного читання; помилки boto3 не містять bucket/key або текст SDK.

   `POST /v1/invocations` для URI з query.
3. Тест виходу symlink із каталогу секретів пробує створити посилання на кожній ОС і пропускається

## Виправлення після рев'ю 2 (WP-07b)

Рев'ю виявило: allowlist `s3.us-east-1.amazonaws.com:443` пропускала підключення без власного endpoint,
хоча boto3 для `bucket=outside` звертається до `outside.s3.amazonaws.com` (`auto`/`virtual`) або
`s3.amazonaws.com` (`path`). Тепер `network_addresses` бере фактичний host з підготовленого botocore
`HeadBucket` запиту. Проба має фіктивні credentials, перехоплює `before-send.s3` і додатково блокує
HTTP-транспорт; мережевий запит неможливий навіть якщо перехоплення не спрацює. Так само перевіряються
власні S3/MinIO endpoint і endpoint, заданий через `AWS_ENDPOINT_URL_S3`.

Нові негативні тести відхиляють усі AWS host поза allowlist для `auto`/`virtual`/`path`, зокрема
відмінність `us-east-1`; позитивні дозволяють лише фактичні host. Тест з TCP listener доводить, що
проба власного endpoint не контактує з ним. `my.bucket` показує, чому не можна виводити host простою
конкатенацією: botocore для нього обирає path addressing навіть за `auto`.

Read-only експеримент із `before-send.s3` (виклики перервано до HTTP):

```text
us-east-1 None auto get_object outside.s3.amazonaws.com
us-east-1 None path get_object s3.amazonaws.com
us-east-1 None virtual get_object outside.s3.amazonaws.com
eu-central-1 None auto get_object outside.s3.eu-central-1.amazonaws.com
eu-central-1 None path get_object s3.eu-central-1.amazonaws.com
us-east-1 http://storage.internal:9000 path get_object storage.internal:9000
us-east-1 http://storage.internal:9000 virtual get_object outside.storage.internal:9000
```

Ті самі host отримано для `put_object`, `delete_object`, `head_bucket`, `create_bucket` і
`list_objects_v2` в цих варіантах. Перевірки гілки:

Probe використовує лише явно задані фіктивні `policy-probe` credentials, тому botocore не шукає
ключі в середовищі чи EC2 metadata. Окремий тест прибирає AWS env credentials, задає відсутні
AWS config/credentials files і спрямовує metadata endpoint на TCP listener: політика визначає host,
listener не отримує жодного з'єднання.

## Доповнення WP-07c: виконання пакетів з registry за PackageRef

**Гілка:** `wp/07c-storage-registry-packages` · **База після rebase:** `b5e3e24` · **Стан:** review

Сервіс storage тепер приймає `handler.package_id`, точну `handler.version` і необов'язковий
`handler.digest` для пакета з registry. Порядок джерел: архів у запиті, встановлений каталог,
registry за `JANE_STORAGE_REGISTRY_URL`. Вбудований пакет авторитетний для свого `id@version`.
Модуль `registry_packages.py` завантажує архів за `registry.v1`, перевіряє ETag, канонічний
дайджест та ідентичність маніфесту, обмежує розмір/час, не виконує redirect і не бере proxy із
середовища. Перевірені пакети кешуються за дайджестом у межах одного екземпляра; одночасні
виклики однієї версії ділять завантаження. Пакет з невстановленим адаптером, залежностями,
невідповідним типом, некоректним маніфестом або небезпечним ZIP відхиляється до запису.
`POST /v1/test-runs` використовує той самий резолвер. Налаштування й типові ліміти описано
в `services/storage/README.md`.

**Критерій 9 (частина storage):** тест `test_fork_from_the_real_registry_runs_in_storage`
публікує пакет у справжньому застосунку registry з backend `memory`, створює fork, бере
PackageRef і записує вебсторінку справжнім файловим адаптером storage. Адресні тести також
перевіряють digest mismatch до запису, чужу версію за дайджестом із холодним і теплим кешем,
ETag, 404/502, токен, ліміти, паралельність та зламані архіви. Контрактний замінник registry
перевіряє відповіді через `registry.v1`.
