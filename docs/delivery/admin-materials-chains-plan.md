# Матеріали, сховища та візуальні ланцюжки

Погоджено користувачем 2026-10-11. Основа: ТЗ §10; базова ревізія main 1eb6dbd.

## Пакети та власність

- WP-24: контракт і реалізація стану сховищ, достовірні статистики та доступні фільтри матеріалів. Власник services/storage/, contracts/, generated API. Перевірки контрактів і незалежний contract-guardian обов’язкові. Не читати БД інших сервісів; невідомі метрики позначати недоступними.
- WP-25: загальний браузер матеріалів, картка матеріалу, окремий екран сховищ із перевіркою доступності та переходами до вмісту. Залежить від WP-24 для нових показників; наявні можливості реалізує одразу.
- WP-26: вибір і з’єднання етапів, розгалуження, вибір пакета та версії, редагування зв’язків; грід Назва/Тип/Значення з вкладеними object/array, операціями над полями й елементами, валідацією та JSON-перемиканням без втрат.
- WP-27: координаторська інтеграція, незалежне рев’ю кожного пакета, цільові browser-сценарії та підсумковий звіт.

Точна власність шляхів: .claude/wp-paths.json. Кожен виконавець має окремий checkout і .jane-wp. Не змінювати чужі файли; CSS нових екранів окремий. Запити на спільні файли передавати координатору.

## Готово, коли

1. Матеріали видно без ручного введення connection_id; фільтри, пагінація, вміст та повторна обробка працюють, відмова одного сховища видима й не ховає інші.
2. Сховища показують реальні результати перевірки, час і доступні статистики; невідомі дані не підмінено нулями. Секрети не відображаються.
3. Ланцюжок створюється, змінюється і зберігається через UI; вкладені JSON та масиви редагуються без втрати типів і сторонніх полів; цикли й некоректні посилання блокують збереження.
4. Наявні завдання відкриваються без втрат, JSON-режим синхронізований із візуальним.
5. Цільові unit/contract/browser перевірки мають справжній вивід у WP-звітах; зовнішні сервіси явно позначені за фактичними межами перевірки.

## Послідовність

WP-24, WP-25, WP-26 стартують паралельно. WP-24 спочатку фіксує контракт та повідомляє WP-25. Координатор переносить завершені коміти в codex/admin-materials-chains, запускає guardian і незалежних wp-reviewer, передає дефекти власникам та виконує інтеграційні перевірки. main не змінюється.
